## 1. 项目概述

本项目是一套面向水利行业的「离线一张图」应用矩阵，按**三端**（产品线）×**四平台**（运行形态）组织：

| 端（产品线） | 中文名 | 代码代号 | 当前版本 | Web 前端规范源 |
|---|---|---|---|---|
| 水利一张图 | 水利工程一张图 | **water / shuili** | v3.77 | `android-build/water-v329/assets/` |
| 古建景点打卡 | 古建景点打卡 | **gujian** | v3.7.13→v3.77 | `android-build/gujian-v31/assets/` |
| 水利感知项目 | 水利感知设备一张图 | **perc** | v1.52→v1.77 | `android-build/perc-v13/assets/` |

**四平台**指同一套 Web 前端（Leaflet + 天地图底图 + 本地向量智能内核）被装入四种原生壳：

1. **Android APK** —— Java/Kotlin 原生壳，WebView 加载 assets。
2. **Windows exe + msi** —— WebView2（C# .NET）壳。
3. **统信 UOS deb**（amd64 / arm64 / loongarch64 / mips64el 多架构）—— PyQt6 壳。
4. **iOS PWA（zip 托管）** —— 离线 PWA 包，托管到 HTTPS 即可「添加到主屏幕」。

> 本次交接统一标注 `v3.77`（feature 标记），表示「三端同步引入反选 + 智能反查/结果点击定位」这组功能；水利基线 v3.76、古建 v3.7.13、感知 v1.52 为本次改动起点。

## 3. 四端四平台构建说明

### 3.1 Web 前端（规范源）
三端 Web 前端是单一规范源，所有原生壳在构建期把 `assets/` 拷贝进壳内 `webroot/`（或 `assets/`）。
- 水利规范源：`android-build/water-v329/assets/`
- 古建规范源：`android-build/gujian-v31/assets/`
- 感知规范源：`android-build/perc-v13/assets/`

> 注意：**Android 壳内的 `assets/` 是构建期从规范源同步生成的副本**，本包未重复收纳水利/古建 Android 壳内的 assets 拷贝（避免与规范源冲突），构建时由同步脚本覆盖。

- 古建：`android-build/gujian-v31/native-shell/android-gujian/` → 其内构建脚本

### 3.3 Windows（exe + msi）
- 水利：`04_Win_UOS_iOS壳/win-water-webview2/` → `build_msi.bat`（WiX7）
- 感知：`04_Win_UOS_iOS壳/win-webview2/`
- 古建：`04_Win_UOS_iOS壳/gujian-win/`
- 公共：`04_Win_UOS_iOS壳/公共构建脚本/build_win_exe_nsis.py`、`build_win_msi.ps1`、`make_msi.py`

### 3.4 统信 UOS（deb，四架构）

## 7. v3.77 缺陷修复记录（2026-09-19 晚）

> 本包源码已含以下修复；**已安装的应用需重新出包（APK / deb / iOS PWA）方可生效**，构建流程见 §3。

### 7.1 感知 APK：启动崩溃 + 菜单空白（同一根因）
- **现象**：打开即报 `TypeError: Cannot read properties of undefined (reading 'folder')`（栈 `scopeLabel` ← `render`）；点击菜单无任何子菜单。
- **根因**：`perc-v13/assets/app.js` 存在两个同名 `scopeLabel`（2266 行数据层标签 / 8156 行文件夹标签），文件级 hoist 使靠后的 8156 行遮蔽前者；`render()` 无参调用 `scopeLabel()` 对 `undefined` 读 `.folder` 崩溃，且 `render()` 在同步启动流程中未包 try/catch，导致延迟的 `buildMenu()` 永不执行 → 菜单空白。
- **修复**：8156 行文件夹标签函数重命名为 `scopeFolderLabel(it)` 并更新 6 处调用点；全局 `scopeLabel` 恢复为数据层版本。文件：`android-build/perc-v13/assets/app.js`。

### 7.2 古建：智能化内核子菜单去除水利专属名词
- **现象**：古建「智能化内核」子菜单出现「闸门 / 启闭机 / 管理所 / 进水闸 / 节制闸」等水利专属名词。
- **修复**：将用户可见的提示 / 占位 / 样例文案按古建（景点）领域适配，涉及 `gujian-v31/assets/` 下 `kb_core.js:144`、`kb_vector.js:678/711/712/730/741/787`、`ai_module.js:1643/1653/1890`。
- **说明**：`kb_vector.js` 中 `TYPE_DICT.shuili`/`TYPE_DICT.perc` 仍保留水利/感知类型释义，但古建仅读取 `TYPE_DICT.gujian`，不会在古建中显示，属领域分区知识库，无需改动。

## 9. v3.77 智能AI子菜单开关（一键隐藏/显示 + 默认隐藏）（2026-09-20）

> 本包源码（三端 `assets/app.js` + `ai_module.js`）含一套「智能AI子菜单」管控机制，详见 `01_本次改动记录_v3.77.md` 对应章节。

### 9.1 功能
- **一键隐藏/显示**：设置菜单首项「🙈 一键隐藏智能AI子菜单 / ⬆️ 一键显示智能AI子菜单」循环开关。隐藏后，**智能AI 分组 + 知识库与智能 分组 + 设置内智能AI设置/知识库管理** 共 15 项需联网 AI 大模型的子菜单从菜单消失；备忘录/游记「问AI」按钮也一并拦截（toast 提示去设置开启）。再次点击恢复，状态持久化于 localStorage。
- **默认隐藏**：自 2026-09-20 起，**三应用首次安装/未手动切换即处于隐藏态**（判定 `smartAIHidden !== "0"`）。如需默认显示，把 localStorage `smartAIHidden` 设为 `"0"` 即可。
- **通用 AI 配置 + 申请 Key**：智能AI设置内「添加模型」即通用配置界面（引用地址/协议/模型ID/APIKey，支持任意 OpenAI 兼容服务，可配自有 OpenRouter 密钥或接 OpenAI/Anthropic/通义/智谱/DeepSeek 等）；面板附「🔑 申请/获取 API Key」12 厂商按钮，一键跳各厂商官网申请页（OpenRouter / OpenAI / Anthropic / Google Gemini / DeepSeek / Kimi / 智谱 / 通义 / NVIDIA / Mistral / Groq / 硅基流动）。

### 9.2 需联网 AI 大模型的子菜单（15 项，三端同构）
智能AI 分组 3（智能查询/智能更新/智能纠错）+ 知识库与智能 分组 11（KBCore 5：智能模糊检索/提示词生成器/AI记忆·Hermes/存疑反向查询/强制联网；KBV 6：智能反查/统计汇总/预案文档入库/生成报告/PDF 转 Word/类型知识库）+ 设置内智能AI设置 1。注：统计汇总/PDF 转 Word/类型知识库本质本地，但作为智能化内核整体随开关隐藏。

### 9.3 注意事项
- 该开关为**纯前端 localStorage 持久化**，不影响其它功能；隐藏态下智能反查/报告/文档结果点击定位（见 `01` 改动二~四）不可用，因相关子菜单已收起。
- 古建/感知菜单名随 CFG.label 变化（如「智能反查水利一张图」→「智能反查感知设备一张图」），逻辑一致。
- 三端四平台实际包体已随源码重新出包，落 `APK归档/四端安装包_20260920_v377/`（APK + UOS deb + Win exe + iOS PWA zip，平台校验全过）；交接 zip 按设计不收纳包体成品。
