## 改动二：智能反查建筑物 —— 结果点击定位

**文件**：`kb_vector.js`（三端同构：`water-v329` / `gujian-v31` / `perc-v13` 的 `assets/kb_vector.js`）

### 新增 `locateEntity(name)`（置于 `/* UI */` 段前）
- 反查内核 `reverseSearch()` 的结果对象只含 `name/type/office/score/bestParam/attrs`，**不含坐标**；`locateEntity` 按 `name` 在全局数据 `items()` 中反查经纬度。
- 坐标来源：`b.lat != null ? b.lat : b.latitude`，`b.lon != null ? b.lon : b.longitude`。
- 定位执行：`global.appGoToMap(lat, lon, 16, "sheetGen")`（先关详情面板再 `map.setView`）；无 `appGoToMap` 时回退 `global.map.setView`。
- 未命中 / 无坐标时 `toast` 提示，不报错。

### `uiReverse()` 结果渲染（约 671–680 行）
- 每条结果外层 div 加 `class="kbv-res" data-name="..."` 与 `📍 点击在地图定位` 提示。
- 渲染后对所有 `.kbv-res` 绑定 `el.onclick = function(){ locateEntity(el.getAttribute("data-name")); }`。

## 补充：v3.77 缺陷修复（2026-09-19 晚）

> 触发：感知 APK 安装后实测发现运行错误 + 菜单空白；古建智能化内核子菜单出现水利专属名词。本次仅改源码，**需重新出包（APK/deb/PWA）才能让已安装应用生效**，详见交接文档 §7。

### 修复一：感知 `render()` 崩溃 + 菜单空白（同一根因）

**现象**
- 打开感知 APK 即报 `Uncaught TypeError: Cannot read properties of undefined (reading 'folder')`，栈：`scopeLabel (app.js:8156:39)` ← `render (app.js:2998:36)`。
- 点击菜单空白，无任何子菜单。

**根因**：`perc-v13/assets/app.js` 存在**两个同名 `scopeLabel` 函数**：
- 2266 行：数据层标签 `scopeLabel(sc)`（`sc = sc || SCOPE` → 返回「感知设备 / 水工建筑物 / 全部（两层）」）。
- 8156 行：照片匹配模块的文件夹标签 `scopeLabel(it)`（读 `it.folder`）。

二者均为文件级声明，靠后的 8156 行**遮蔽（hoist 覆盖）**了 2266 行，使全局 `scopeLabel` 变成「读 folder」版本。`render()` 在 2998 行以**无参**调用 `scopeLabel()` → `it.folder` 对 `undefined` 取属性 → 崩溃。
而 `render()` 在启动流程（13636 行）**同步执行且未被 try/catch 包裹**，位于延迟执行的 `buildMenu()`（13640 行）之前；一旦崩溃，后续 `_deferBoot` 回调（含 `buildMenu()`）永不注册 → **菜单永远不渲染 → 空白**。故「崩溃」与「菜单空白」是同一根因的两个表现。

**修复**：将 8156 行的文件夹标签函数重命名为 `scopeFolderLabel(it)`，并更新其 6 处调用点（8242/8246/8250/8448/8452/8456 行）。重命名后全局 `scopeLabel` 恢复为 2266 行的数据层版本，`render()` 不再崩溃、`buildMenu()` 正常执行；文件夹标签功能（照片匹配）保持不变。

**影响文件**：`android-build/perc-v13/assets/app.js`
**验证**：`node --check` SYNTAX_OK；`scopeFolderLabel` 命中 7 处（1 定义 + 6 调用），无残留 `scopeLabel(it)`；2266 行数据层 `scopeLabel` 唯一。
