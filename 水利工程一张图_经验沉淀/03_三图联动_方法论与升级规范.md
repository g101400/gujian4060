## 一、水利一张图 v3.6 → v3.20 功能逻辑全梳理

> 代码事实来自 `docs/04_软件变更文档.md`、`docs/05_版本历史与备份.md`、技能 `references/pitfalls.md`（38 条坑）。

### 1.1 v3.6 — 交互与匹配重构（基线能力，三图都应具备）
- **菜单两级化 + 高频置顶**：顶栏「🔍 查询 / 🔎 筛选」与一级菜单并列；一级归为「地图和位置 / 数据管理 / 传输与共享 / 信息与帮助」。
- **模糊 + 智能匹配**：`scoreMatch()` = 最长公共子串(LCS) + 编辑距离 + 公共二元组兜底；「峰山口大大.jpg」可容错匹配「峰山口」。
- **文件夹 / ZIP 逐步匹配**：原生 `unzipImages` 回传 `folder`（顶层文件夹名），先按文件夹名缩范围，再按文件名匹配。
- **多选弹窗统一按钮**：全选 / 全部清除 / 取消 / 确认 / 退出（`window.ambSelectAll/ambClearAll/ambCancel`）。
- **每页退出按钮**：`openSheet()` 自动 `ensureSheetFoot(id)` 追加「✕ 退出本页」，杜绝卡页。
- **查询 / 筛选提至顶栏 + 跳转**：0 匹配弹「没有符合条件的选项」；1 个立即定位；多个跳第一个并提示数量。
- **导入前内容查重**：`photoSha256/fileSha256` 比对，覆盖/跳过。
- **长按照片保存与切换**：`appPhotoAct(id,i)` 操作条（保存/上一张/下一张/退出）。
- **全 APP 风格统一**：CSS 变量驱动（`--bg/--primary/--accent`），导出《APP 风格色彩字体搭配》文档（`docs/07`）。

### 1.2 v3.7–v3.9 — 导入导出真正可用
- **v3.8 网盘导入闭环**：App 注册为系统分享目标（`ACTION_SEND/SEND_MULTIPLE` + `launchMode=singleTask`），从百度/夸克网盘分享文件直接落入导入；`netdiskPick` 原生桥落地；冷/热启动双路径（`pendingShareJson`）。
- **v3.9 压缩包可选 + 7z 可用**：`pickFiles` 支持多 MIME（`image/*,application/zip,application/x-7z-compressed...`）；`unzipImages` 支持 ZIP/7z（Apache Commons Compress 1.21 + XZ 1.9，随 APK 打包）；RAR 明确报错；导出真正支持 7z；来源/目标图标卡片化。

### 1.3 v3.10 — 致命修复：导入卡死 / 占满存储（坑 #17/#18/#19）
- **异步解压**：`unzipImages` 改原生线程池异步，进度 `onXferProgress('unzip',…)`，完成回调 `window.onUnzipImages(json)`；JS 累积多包后统一匹配。
- **缩略图显示**：新增原生 `thumbPhoto(relPath,max)`（BitmapFactory 降采样 RGB_565 JPEG q72，默认 720px）；`photoSrc` 改返缩略图，全图仅灯箱/保存按需单张加载（`photoFullSrc`）→ 内存峰值从数 GB 降到几十 MB。
- **分块匹配**：`runPhotoMatchNative` 每批 30 张 + `setTimeout` 让出主线程。
- **清理导入缓存**：`finishPhotoMatch`/启动/菜单调 `cleanInbox()` 删 `inbox/uz_*`；新增「清理导入缓存」菜单项。
- **弹窗照片数量上限**：单建筑弹窗最多 18 张缩略图，超出「查看全部 N 张」灯箱按需加载；编辑页最多 24 张。

### 1.4 v3.11 — 文件夹层级匹配 + linkPhoto 移动（坑 #20）
- **双路命中**：`bestMatchesForItem` 把文件夹每层目录名 + 文件名都去比建筑物名取最高分；`classifyOne` 据此分类（`score>=700` 且明显最优自动绑定，否则范围内确认）。
- **folder 回传完整父路径**：多层嵌套 `管理所/建筑物/照片.jpg` 也能命中。
- **linkPhoto 改移动**：`renameTo`，避免 2G 解压出 3.9G 再复制造成存储峰值翻倍。

### 1.5 v3.12 — 未匹配批量绑定 UI + 统计 + 筛选 + 删除（坑 #21）
- **未匹配批量绑定 UI**：`finishPhotoMatch` 新增 `unmbBox`，共享 `<datalist id="umbBldList">` 列全部建筑物作轻量选项（**绝不 select×N 行**）+ 「一键全部绑定到 + 全部应用」+ 逐张 `<input list>` + 复选框默认全选。
- **统计新增「总照片数」**并把「含照片」改名「含照片建筑」+ 口径说明。
- **导入照片加 `added: Date.now()`** 时间戳，为按时间筛选/删除提供锚点。
- **照片状态筛选**：`filters.photoStatus` = `all|has|many(≥3)|none`。
- **删除二级菜单**：「删除添加的照片」（时间+管理所，二次 confirm 不可恢复）、「删除建筑物」（管理所+类型，含照片数提示+不可恢复警示+二次 confirm）。

### 1.6 v3.13 — 多张照片可自定义张数
- `filters.photoMin`（默认 3），选中「多张照片」渲染「≥N」数字输入框 `#photoMinInput`，实时筛选。

### 1.7 v3.14 — 手动匹配照片真正入库（坑 #22，最关键）
- **cleanInbox 延后执行**：新增 `maybeCleanInbox()`，**仅当**未匹配/多选/重复三个手动框全部处理完才调 `cleanInbox()`；`finishPhotoMatch` 不再立即清理。否则未匹配照片源文件被提前删除，`linkPhoto` 打开已删文件静默失败 → 手动匹配照片全部丢失（自动匹配因已移出 inbox 幸免）。
- **真落盘计数**：`confirmUnmatched/confirmAmbiguous` 改为 `var ok=saveOne(...); if(ok) chosen++; else skipped++;`，杜绝「显示 368 已保存、实际仅 16 张」假成功。
- **统一重命名**：落盘文件名 `建筑物名_顺序号.jpg`、caption `建筑物名 #顺序号`（自动/手动同规）。
- **多选框改互斥单选**：`<input type="radio" name="amb{i}">`，每张照片只绑一个建筑物，默认最匹配项。

## 二、沉淀的成功经验与技能（可复用方法论）

这些是「与领域无关」的通用能力，三图应共享同一套实现，集中沉淀在技能 `shuili-yitu-app`（38 条坑 + 脚手架）。

1. **离线 WebView 构建流水线**：aapt2 + d8 + zipalign + apksigner（零 Gradle/Studio），JDK17 + SDK build-tools 34.0.0。22 条致命坑（尤其中文路径、d8 不吃目录、aapt2 无 add 用 zipfile 注入、7z 库 d8 崩溃用 1.21/1.9、沙箱 rm 不可靠用 `-f`）。
2. **设计系统**：CSS 变量驱动，配套《风格色彩字体搭配》文档，换肤只改 `:root`。
3. **照片落盘 + 缩略图 + 惰性加载**：绝不以 base64 塞 localStorage；`thumbPhoto` 缩略图显示，全图按需单张加载；弹窗数量上限防 OOM。
4. **智能匹配三阶段**：自动绑定（高分且明显最优）/ 范围内确认（互斥单选，默认最优）/ 未匹配批量绑定（`datalist` 轻量选项 + 一键全应用）。
5. **cleanInbox 时序铁律（坑 #22，最重要）**：手动匹配框未全部处理完，**绝不可**调 `cleanInbox()`；只用 `maybeCleanInbox()` 兜底。
6. **高频按钮置顶 + 0/1/多跳转**：查询/筛选置顶栏；筛选确认按结果数给不同反馈。
7. **每页退出 + 三击回主菜单**：`ensureSheetFoot` + document 级三击监听（空白/地图任意处均可）。
8. **防呆三件套**：改完 `node --check app.js`；挂 `window.onerror` 兜底；IIFE 局部函数经 `window.xxx=xxx` 暴露给内联 onclick。

## 四、三图联动升级规范（convention —— 以后必须遵守）

**定位**：水利一张图 = **母版（canonical）**；视频设备 APP、古建打卡 APP = **派生（derived）**，共享同一技能脚手架与 38 条坑，仅领域模型与少量领域逻辑不同。

**R1 母版发版必评估**：水利一张图每次升级到新版本（如 v3.15+），第一动作是在下表「升级联动检查」逐行评估，凡「通用能力」改动必须 port 到两派生 APP；「领域能力」仅在有类比时移植。

**R2 通用能力全量对齐 / 领域能力类比移植**：
- 通用能力（强制对齐）：离线构建流水线、38 条坑、照片落盘+缩略图+惰性加载、智能匹配三阶段+未匹配批量绑定、cleanInbox 时序、查询/筛选置顶+跳转、每页退出+三击、风格色彩字体文档、防呆三件套。
- 领域能力（类比移植）：统计口径、删除二级菜单、照片状态筛选 —— 按各自实体名改写即可。

**R3 版本号各自独立 + 互引**：三图版本号独立演进（水利 v3.x / 视频 v1.x / 古建 v1.x）；派生 APP 的变更文档必须注明「对齐母版 vX.Y 的通用能力（坑 #N）」。

**R4 各自备份与文档**：每个派生 APP 维护自己的 `backup/<ver>_YYYYMMDD/`、`风格色彩字体搭配.md`、经验沉淀；母版 `references/pitfalls.md` 是 38 条坑唯一真相源，三图共用。

**R5 触发机制**：以后用户说「水利一张图升级到 vX.Y」或类似，默认动作 = (a) 母版出包；(b) 按 R1/R2 给视频设备 APP、古建打卡 APP 各出对应版本包；(c) 三方变更文档互引。
