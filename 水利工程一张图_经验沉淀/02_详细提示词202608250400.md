# 详细提示词 · 给其他智能体一次性生成「离线一张图」APP

> 用途：把下面这段提示词**整段复制**给任意代码智能体（含本助手），它即可按已验证方法论，从零生成一套「水利工程基础信息一张图」类离线安卓 APP。
> 配套：需求文件见 `01_详细需求文件.md`；技能 `shuili-yitu-app` 自带构建脚手架。
> 已验证版本：v3.14（versionCode=14），APK ≈ 9.2MB，自签名可安装。

## 提示词（复制以下全部内容）

```
你是「离线一张图 APP 生成器」。请基于以下已验证方法论，为用户生成一套**安卓离线 APP**：
把一套网页（Leaflet 地图 + 水利工程设施数据）打包成已签名、可直接安装、现场无信号也能用的 APK。

═════════════════════ 一、技术决策（不要自作主张改栈）═════════════════════
- 前端：Leaflet.js（本地自带 leaflet.js/leaflet.css），**绝不用 Leaflet 默认 PNG 图标**。
- 底图：天地图 WMTS 在线瓦片，vec_w(矢量)/img_w(影像)，URL 模板用 `t{s}` 且 subdomains:["0".."7"]；tk 参数来自天地图 Token。
  ⚠️ 绝不能用 `t{0-7}` —— 这是致命坑，会导致 getTileUrl 抛错、整页冻死。
  ⚠️ Token 勿写死在 app.js：在 index.html 头部集中配置 `window.TIANDITU_TOKENS={browser,server}`，app.js 读 `browser||内置缺省`；服务器端 token 仅供后端调用，勿打入对外客户端包（换环境只改 index.html 一处）。
- 标记：一律 L.divIcon 内联 SVG 蓝色水滴（#1e6fbf + 白点，32×44，描边 2.5px）。离线任何装饰走内联 SVG/CSS。
- 数据：window.SHUILI_DATA 数组（点/线要素）+ window.SHUILI_META 元数据；localStorage 持久化键 shuili_map_v2。
- 导出：JSZip（本地 jszip.min.js）打包照片 ZIP / 带 BOM 的 CSV 表格。
- 原生桥：Android.openLocationSettings / Android.openExternal / Android.saveBlob（由 WebView JSInterface 提供）。
- 打包：aapt2 + d8 + zipalign + apksigner，零 Gradle/Android Studio（脚手架在技能 assets/）。

数据模型：建筑物 {id,name,office,station,chan,btype,lat,lon,photos[],attrs[[k,v]...]}；线要素用 coords[]，弹窗取中点。
1. 地图：矢量/影像底图切换（右上悬浮面板 + 菜单双入口，状态同步）；缩放控件右下角。

3. CRUD：添加（点地图定位自动取坐标）/编辑/删除；坐标拾取·测距·添加三模式互斥。
4. 筛选：管理所/管理站/类型(chip多选)+关键字，实时生效。
5. 列表视图：卡片+快速定位（线取中点）；切回地图调用 map.invalidateSize()。
6. 定位我的位置：geolocation；权限拒绝 1.2s 后 Android.openLocationSettings()；超时10s区分提示。
7. 导航：弹窗按钮 → geo:lat,lon?q=lat,lon(中文名)，Android.openExternal() 唤起地图App。
   ⚠️ q 参数直接拼中文，绝不 encodeURIComponent（否则显示 %E5%B3%B0… 乱码）。
8. 测距：菜单进入，折线+各段距离+总距离，双击/按钮结束，禁用双击缩放。
9. 周边搜索：选中心+半径，L.circle 圈选，按 distanceTo 排序。
10. 获取坐标：GPS/点选地图/搜索建筑物，结果可复制。
11. 照片：单张上传(input file→onShowFileChooser)；批量导入（多选图或ZIP）按名匹配。
    ⚠️ normalizePhotoName() 忽略末尾数字/括号（峰山口1.jpg→峰山口）；匹配=相等或互相包含；
    唯一匹配自动保存，0匹配提示，多匹配弹勾选框可多选保存；filter 回调必须 return 图片数组。
12. 导入/导出 ovkmz（奥维 KML+附件）。
13. 导出照片（按管理所分文件夹，多图加 _1/_2 序号）→ Download 目录 ZIP。
14. 导出建筑物表格（可选列+按管理所筛选，带 BOM CSV，Excel 不乱码）。
15. 统计（按管理所/类型聚合 Top-N）；恢复初始数据（确认后重置 localStorage）。
16. 菜单：FAB 悬浮按钮 + 三击任意处（含空白/地图）呼出主菜单（弹层内点击不计入，避免卡页找不到主菜单）；首次进入提示三击快捷键；高频功能(定位/列表/测距/搜索)靠前，管理类靠后；

═════════════════════ 二·补 v3.6 交互与匹配强化（在上方基础上叠加，不得删已有功能）═════════════════════
19. 菜单结构（一级+二级）：顶栏置顶「查询」与「筛选」两个最高频入口，与一级菜单并列；
    一级归并为四组「地图和位置 / 数据管理 / 传输与共享 / 信息与帮助」，原功能全部保留归入对应分组；
    二级菜单默认隐藏，点击分组标题或「＋」展开，分组折叠状态由 buildMenu 维护。
20. 照片/ZIP 导入——模糊智能匹配（在「相等/包含」之外）：
    ⚠️ 必须实现 scoreMatch(a,b)：相等=1000；互相包含=900；最长公共子串 LCS≥2 且(ratio≥0.5 或 编辑距离≤2 且较短串≥3)→700+LCS×5-编辑距离×30；
       ratio≥0.34→400+LCS×5；公共二元组≥2→200+二元组×20；否则0。
    配套 longestCommonSubstringLen / editDistance(Levenshtein) / commonBigrams。
    示例「峰山口大大.jpg」应匹配「峰山口」（容错多字）；多候选进人工选择弹窗，不足阈值计未匹配。
    ⚠️ 确认弹层默认勾选最匹配项(高亮)并标注置信度(高匹配/较可能/待确认)与推断范围(省/类别)，用户可一键确认，或改选/跳过。
21. 导入逐步匹配（文件夹/ZIP）：原生 unzipImages 返回项带 folder(顶层ZIP文件夹名)；
    先 matchScopeForFolder(folder) 按文件夹名模糊匹配「管理所」或「类型」得到收窄候选集，
    再在该范围内 smartFuzzyMatches(base, scope.cands) 按文件名匹配；无匹配进人工选择。
22. 多选弹窗统一五按钮：全选 / 全部清除 / 取消 / 确认 / 退出（ambSelectAll/ambClearAll/ambCancel 等回调暴露到 window）。
23. 所有页面（菜单/通用/编辑）均追加「退出本页」按钮：openSheet 调 ensureSheetFoot(id) 自动追加，避免卡死。
24. 查询/筛选提至顶栏显眼（.tbtn.qf 高亮）；筛选「确认」applyFilterAndJump：0 提示"没有符合条件的选项"、1 立即定位、多个跳第一个。
25. 导入每张照片保存前按内容(SHA-256)查重：Android.photoSha256/fileSha256；重复弹「覆盖/跳过」并展示已有照片对比。
26. 长按照片保存与切换：弹窗/灯箱照片 oncontextmenu→appPhotoAct(id,i) 操作条：保存图片/上一张/下一张/退出；
    多张可切换(photoActSave/photoActPrev/photoActNext/closePhotoAct)，保存经 Android.saveBlob。
27. 全 APP 风格统一：CSS 变量驱动(--bg/--primary/--accent/--amber/--danger/--text/--muted/--border/--soft)，
    顶栏渐变 linear-gradient(135deg,#1b3a5b,#244c75)；并产出 docs/07_APP风格色彩字体搭配.md 便于后期改皮肤。
```

## v3.5 架构要点补充（给复用本提示词的智能体）

- **照片禁止进 localStorage**：一律落盘到应用私有目录 `filesDir/photos/<建筑ID>/`，记录相对路径 `p.file`；读取经 `Android.readPhoto(relPath)` 按需转 base64。这是支撑 >3GB 导入导出的前提。
- **导入导出大文件走原生 `LargeFileManager`**：`Android.exportKmz(JSON.stringify({kml, photos:[{relPath,ovName}]}), outPath, resume)`、`Android.importKmz(srcPath, resume)` 返回 `window.onImportData('{kml,photos:[{ovName,relPath}]}')`；富解析（属性/文件夹/多照片）保留在 JS 侧，按 OvAttaItem 顺序映射。
- **续传/进度**：原生回 `window.onXferProgress/onXferDone/onXferError`；非 WiFi 用 `Android.netType()` 弹确认。
- **多端协同**：`Android.peerStart(port)` 起本地 HTTP（Range 续传），`Android.download(url,outPath,resume)` 作客户端下载；`Android.netdiskUpload(provider,token,localPath,remoteName,resume)` 上传百度/夸克（需用户 OAuth token）。
- **内容去重**：`Android.fileSha256(path)` / `Android.photoSha256(relPath)` 用于导入时「内容相同提示覆盖 / 跳过重文件」。
- 清单见技能 `shuili-yitu-app` 的 `SKILL.md` 第 19 条。

## v3.6 交互强化补充（给复用本提示词的智能体）

## 交付前质量门禁（六条，自查/复用必过）

> 来源：2026-08-15 一轮自查，固化「水利一张图 v3.6」与「视频运维一张图 v1.5.0」的六大交互纪律。后续任何同类 APP 交付前逐条核对。

1. **菜单：只重排不删减** —— 高频入口（查询/筛选）置顶并列；原有功能全部保留归入合理分组；二级默认隐藏、点标题或「＋」展开。
2. **文档与回退同步** —— 优化后同步需求/概要/详细/变更/版本/风格全部文档，含本提示词与技能文件；并做代码+文档备份，APP 可回退。
3. **风格统一 + 风格文档** —— 全 APP 配色字体由 `:root` CSS 变量集中管理；导出 `docs/07_APP风格色彩字体搭配.md` 便于改皮肤。
4. **智能匹配 + 范围内确认** —— 模糊匹配升级为智能匹配（`scoreMatch`：相等/包含/最长公共子串/编辑距离/二元组）；不确定时在「选定范围」确认（展示范围标签），候选为可勾选行 + 全选/全部清除/取消/确认/退出，确认更方便。
5. **全页退出 + 三击呼出** —— 每个弹层底部「✕ 退出本页」；屏幕任意处（含空白/地图）快速连按三下呼出主菜单（弹层内不计），首次进入提示快捷键。
6. **查询/筛选置顶 + 确认跳转** —— 查询/筛选为顶栏最显眼按钮；筛选「确认」：0 提示「没有符合条件的选项」、1 立即定位、多个跳第一个匹配项。

> ⚠️ 三击必须是 **document 级监听任意处**，不要只绑在标题上——否则空白/地图区连点无效，用户仍会卡页。

## v3.7 沉淀的可复用经验（2026-08-15）
- **菜单图标醒目**：移动端菜单项图标统一用「圆形色块」（主色底白字），比纯 emoji 更醒目且风格一致。
- **筛选图标区分**：查询用 🔍、筛选用 🎚️，避免两个放大镜雷同导致误触。
- **筛选实时计数 + 结果框选**：筛选弹层实时显示「当前符合条件：N 个」，确认后多命中用「倒水滴高亮 + 蓝色虚线圈刚好罩住全部 + fitBounds」，单命中沿用定位逻辑。
- **分享到第三方（无 AndroidX）**：构建仅含 android.jar 时无法用 FileProvider 库；自建极简 `ContentProvider`（`ShareProvider`）以 `content://` 暴露文件，配合 `Intent.FLAG_GRANT_READ_URI_PERMISSION` 分享到微信/飞书/QQ，规避 file:// 暴露限制。
- **7z/网盘导入限制**：浏览器环境 JSZip 仅支持 zip；7z/RAR 与网盘导入需原生支持，缺失时给出明确提示而非静默失败。
- **智能匹配 UX**：多匹配确认默认勾选最匹配项 + 标注置信度（高匹配/较可能/待确认）+ 推断范围，用户一键确认或改选。

## v3.8 新增可复用经验（2026-08-15）
- **网盘导入用系统分享闭环，而非内置 API**：构建仅含 android.jar、无网盘 SDK/凭证时，最稳的做法是把 App 注册为 `ACTION_SEND`/`SEND_MULTIPLE` 分享目标（singleTask），让用户从网盘 App「分享→本 App」完成导入，免去 token/网关。按钮用 `netdiskPick(provider)` 唤起网盘 App 引导该流程。
- **分享接收三坑（坑 #15）**：① 漏注册 SEND 过滤器则分享列表里看不到本 App；② 默认 standard 启动模式在 App 已运行时再分享会新开实例、状态错乱，必须 `launchMode="singleTask"`；③ 分享早于 `onPageFinished` 时 `window.onPickFiles` 未定义，需 `pendingShareJson` 暂存待页面加载完注入。
- **7z 离线无解**：无 7z 库就别假装支持，导出/解压 7z 一律回退 ZIP + 明确提示（已在 v3.7 标注为已知限制）。

- **微信云开发落地（方案①，零备案零域名）**：`project.config.json` 加 `cloudfunctionRoot`；云函数 `getOpenid`(返 `cloud.getWXContext().OPENID`) + `syncShared`(上行 upsert `_openid+module+recId` / 下行拉 `_openid!=自己 && module && updatedAt>since`)。集合 `shared_records` 权限「仅创建者可读写」——客户端读不到他人数据，但云函数服务端 `cloud.database()` 不受此限制，下行由云函数完成，合规且正确。增量同步用 `local.sync.lastPull` 时间戳。
- **🛑 合规边界（不可逾越）**：① 微信读/写群消息违反运营规范（个人微信不开放 API，需企业微信），**明确不做**；手动分享卡片合规。② 照片云端同步**明确不做**（终态 = 结构化字段同步 + 本地照片存本机），不要主动提议照片上云。③ 授权登录取昵称/头像/openid 合规。
- **四端同步审计方法（v1.4.1 核心）**：安卓三端(水利V3.30/感知V1.6/古建V1.8)改完，必须审计小程序是否缺字段/筛选维度。本次缺口：感知采集缺「设备型号/固定资产编号/设备主要参数(多行)」、古建采集/详情缺「简介/文物特点」、感知筛选缺「所属系统」、古建筛选缺「省份/城市」、古建省份城市硬编码全国列表(改为从实际数据提取 34省/201市)。补齐后 collect/detail/filter/map 四页同步改。
- **数据转换质量（安卓 data.js → 小程序 data/{eng,perc,gujian}.js）**：① 源字段拼写错误（如 perc `subsytems`）在转换层归一为 `subsystems`，不把源瑕疵带进新端；② 坐标 GCJ-02 已对齐微信直接转；③ 分类清单必须从实际数据提取，不硬编码；④ 安卓三端与小程序必须同源字段清单，改一端同步审计其余端。
- **小程序发布门禁**：`find . -name "*.js" | xargs node --check` 全过 + `JSON.parse(app.json/project.config.json)` 合法 + `require('./data/{eng,perc,gujian}.js')` 记录数/字段正确 + filter 维度模拟(perc 视频监控全中 / gujian 省市全中)通过。
- **四端架构终态**：安卓=原生APK(三独立package可同装) / Win=原生WebView2 C#便携zip / UOS=原生PyQt6 deb / iOS=PWA+静态HTTPS(唯一非原生)。网页 app.js/data.js/leaflet 四端同源，安卓为已验证超集（含 Web 照片回退 `new URL(p.file)`）。采用「安卓素材整体覆盖各 webroot」零丢失同步。
- **保留即合规**：本轮未删任何功能/菜单；`node --check` 全过 + roll-back 备份已存。
