## 一、本轮主题：感知 App 集成「水工建筑物数据层」

按需求（水利保持独立 · 感知只集成水工建筑物作基础数据层 · 两层数据独立 · 跨层周边查询 · 明确可选项且原功能不变）落地。
核心手法：把全局单数组 `BUILDINGS` 升级为**作用域视图**，默认作用域 = 感知设备 ——
**原有 117 处引用在默认态零行为变更**，原有导入/导出/筛选/查询/统计行为完全保持不变。

### 1. 双库双 key（数据分离）

| 库 | 内容 | localStorage 键 | 数据源 |
|---|---|---|---|
| `DEVICES` | 感知设备（沿用） | `perc_map_v2` | `PERCEPTION_DATA` |
| `WBUILDS` | 水工建筑物层（新增） | `perc_water_v2` | 可为空，或随包 `WATER_BUILDINGS` |

- 作用域 `SCOPE ∈ {device(默认), water, all}`，持久化进 `shuili_settings.scope`。
- `window.BUILDINGS` getter 返回当前作用域视图：device/water 为**库本身**（可写），all 为**只读合并副本**。
- 新增全局桥（供尾部注入模块/AI 使用）：`WATER_BUILDINGS_LIVE` / `DEVICE_BUILDINGS_LIVE` / `BUILDINGS_SCOPE`。

### 2. 写操作按归属路由（关键风险点已封堵）

| 场景 | 处理 |
|---|---|
| 新增（表单保存） | `addRec(b)`：device/water 写视图（即对应库）；all 按归属路由，无归属 → 设备库（保持原语义） |
| 删除（单条 / 批量） | `removeIds(ids)`：两层同时按 id 清除后重建视图 —— 根治 `BUILDINGS = BUILDINGS.filter()` 造成的「视图与库脱钩」 |
| 导入（ovkmz / 批量导入） | `importTargetStore()`：优先取 `beginImport()` 固定的目标库，其次按当前作用域 |
| 恢复初始数据 | 设备库回内置数据、建筑物层回种子，视图重建 |

**硬约束**：「导入水工建筑物」入口在 `importKmz()` 同步阶段即 `beginImport("water")`，
本次导入的所有记录只写 `WBUILDS`，**绝不触碰/覆盖设备库**（已由回归脚本逐项断言）。

### 3. 新增菜单组「水工建筑物层」（🏗️）

| 菜单项 | 功能 |
|---|---|
| 导入水工建筑物（只写建筑物层） | ovkmz / kmz / kml 导入，目标库固定为建筑物层 |
| 导出水工建筑物（ovkmz） | 先切到建筑物层再走既有导出面板 |
| 数据层切换（设备 / 建筑物 / 全部） | 打开数据层切换面板 |
| 跨层周边查询（建筑物 ↔ 设备） | 自然语言周边查询面板（带句式示例） |
| 新增建筑物 / 地点（点地图定位） | 切到建筑物层并进入点选新增；建筑物层内新建 id 用 `w*` 前缀防碰撞 |
| 清空水工建筑物层 | 二次确认，只清建筑物层 |

> 菜单**零删除**：原有全部菜单项与 key 保持不变，收藏/隐藏不受影响。

### 4. 筛选 / 查询 / 导航 的数据层开关

- 顶部栏新增 `🟢 设备 / 🔷 建筑物 / ⬜ 全部` 按钮（常驻），点击打开数据层切换面板。
- 筛选面板顶部新增「数据层」三段 chip，并显示两层条数；切换后筛选面板就地刷新。
- 查询框、列表视图、统计、周边搜索、导出表格均跟随当前数据层（均读 `BUILDINGS` 视图）。
- 周边搜索新增「① 中心数据层」与「② 目标数据层」两级可选（默认：与中心不同层），中心下拉随数据层重建。

### 5. 地图分层

- 建筑物层 marker 用**灰色 ▣**图标，并设 `zIndexOffset:-1000` **置于设备层之下**。
- 图例新增「当前数据层」标题、全部模式下的建筑物灰色图例，以及两层条数。
- 计数条改为 `[当前数据层] 显示 X / Y（筛选）共 Z`。

### 6. 跨层自然语言周边问答（双向）

- 入口：查询框回车/点「查询」自动识别，或菜单「跨层周边查询」。
- 句式：`XX周边有几个感知设备` / `XX附近有几座水工建筑物` / `XX周边500米内有多少个感知设备`。
- 半径默认 200 m，`XX米 / XX公里` 可覆盖；**结果全部本地按 `map.distance` 算完再出结论**，不经网络、不臆造数字。
- 中心记录**无坐标**时（设备 236 条 noCoord），自动改按「同管理处 / 管理所 / 管理站」口径统计并说明原因。
- 结果列表支持一键定位；支持**导出结果 CSV**（沿用统建 `saveBlobFile`，安卓走原生保存）。
- 中心与目标可互换（建筑物 ↔ 设备双向）。

### 7. 建筑物查看 / 编辑 / 新增

- 点击建筑物 marker（弹窗）或列表 → 详情/编辑：名称 / 管理处 / 管理所 / 管理站 / 段 / 类型 / 经纬度 / 参数 / 照片。
- 照片沿用 `photo_gesture.js`（电脑拖拽缩放、手机捏合/长按菜单）。
- 新增沿用「添加建筑物（点地图定位）」；**所有写入经作用域路由，永不触碰设备库**。

### 新增：内置「水工建筑物底图种子」`water_data.js`

- **背景**：v1.48 首版的「水工建筑物层」是空库，必须手工「导入水工建筑物」才有数据；首次安装打开是空白。
- **实现**：新增 `assets/water_data.js`，`window.WATER_BUILDINGS` = **557 条**水工建筑物
  （名称/管理所/渠道/类型/参数 attrs/经纬度；407 条含坐标），源自水利 App 的建筑物骨干种子。
  1. `load()`：首次安装（`perc_water_v2` 为空）自动播种进建筑物层并**固化**；
     此后以本地库为准，**清空后不会自动重建**（种子不回流）。
  2. 新增「**重新播种内置建筑物种子**」：菜单组「水工建筑物层」+ 数据层切换面板按钮，
     二次确认后用种子替换建筑物层（不影响感知设备数据）。
  3. 种子 id 统一 `w1…w557`，与「建筑物层内新建用 `w*` 前缀」约定一致，不与设备 `p*` 撞号。
- **隔离性不变**：两层仍完全独立；回归断言「播种/重新播种后感知设备库 JSON 逐字节不变」。
