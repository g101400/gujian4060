## 2 变更明细

### CHG-HOT-001: 修复 app.js 致命语法错误导致启动假死
| 项 | 内容 |
|----|------|
| 类型 | 致命 Bug 修复 |
| 优先级 | 最高 |
| 状态 | 已完成 |
| 影响文件 | app.js |
| 回归版本 | v3.1（批量导入建筑物功能引入） |

**问题现象：**
- v3.1 安装后打开即"白屏/假死"，无任何交互响应（地图、菜单、按钮全部失效）。

**根因：**
- `doBatchImportBuildings()` 中错误提示字符串 `未找到"名称"列（name/名称）` 内含未转义的双引号，导致 `app.js` 在解析阶段抛出 `SyntaxError: Unexpected identifier`，整个 IIFE 不执行，所有初始化代码（地图、菜单、事件绑定）均未运行。
- 用 `node --check app.js` 已定位并验证。

**变更后：**
- 字符串转义为 `未找到\"名称\"列（name/名称）`，`node --check` 验证通过。
- 版本号升级为 v3.2。

## v3.7（2026-08-15）优化迭代

> 本次按用户自查清单对「水利工程基础信息一张图」做体验与能力优化，未删除任何原有功能/菜单。

### 一、菜单图标与筛选图标（Req 1）
- 所有菜单图标统一改为**圆形色块**（主色-浅底白字），醒目且风格一致。
- 筛选图标由 `🔎` 改为 `🎚️`，与查询 `🔍` 明显区分（原两者均为放大镜，易混淆）。

### 二、筛选实时计数 + 结果框选（Req 2）
- 筛选弹层顶部新增**实时计数条**「当前符合条件：N 个建筑」，每勾选/取消一个芯片即时刷新。
- 点击「确认」后：
  - 0 条 → 提示「没有符合条件的选项」；
  - 1 条 → 立即定位该建筑物（沿用原逻辑）；
  - 多条 → 每个命中建筑替换为**倒水滴高亮标记**（琥珀色、尖端朝上），并以**蓝色虚线圈**（`#1e6fbf`，虚线 `7,8`）刚好罩住全部命中建筑，自动 `fitBounds` 适配视图。

### 三、批量导入照片（Req 3）
- 入口图标保持醒目；新增**来源选择**：本地文件 / 百度网盘 / 夸克网盘。
- 压缩包格式支持 **ZIP** 与 **7z/RAR**（原生 `unzipImages` 解压；7z/RAR 若原生不支持会提示改用 ZIP）。
- 网盘导入调用原生 `netdiskPick`（若未连接网盘账号则给出明确提示，请先用本地导入）。

### 四、导出照片（Req 4）
- 导出对话框可选：**范围**（全部合并 / 按管理所单独）、**格式**（ZIP / 7z）、**目标**（本地下载 / 百度网盘 / 夸克网盘 / 分享微信 / 飞书 / QQ）。
- 压缩包按管理所命名与分文件夹；新增原生 `shareFile` + `ShareProvider`，**分享到微信/飞书/QQ 真实可用**（以 content:// 规避 Android 7+ 的 file:// 限制）。
- 7z 格式在当前原生打包未支持时回退为 ZIP 并提示。

### 五、智能匹配确认（Req 4 智能匹配）
- 多匹配确认弹窗**默认勾选最匹配项**，并标注**置信度**（高匹配 / 较可能 / 待确认）与**推断范围**（管理所 / 类型），用户可一键确认或改选。

### 六、风格统一（Req 3）
- 顶栏/弹层头渐变、进度条、悬浮按钮等内联色统一引用 `:root` CSS 变量；刷新《07_APP风格色彩字体搭配》。
- 查询/筛选保持顶栏显眼；每页保留「退出本页」；三击空白处仍可呼出主菜单。

## v3.23（2026-08-19）真机问题修复

> 本轮按真机测试反馈修复「导入提示不弹」「查询圈选」两类问题，未删除任何原有功能/菜单。

### 一、导入提示真机不弹（根因修复）
- **根因**：kmz/ovkmz 二次导入、以及解析异常等分支误用原生 `confirm()`/`alert()`。离线 Android WebView 中这些原生对话框**不显示且默认返回 false**，导致：重复导入被静默取消、同名建筑物被静默覆盖、异常无提示。
- **修复**：全部改用应用内自定义 `ask()` 对话框（`#askBox`，复用同一套 CSS 变量与主题绿），保证提示必现。
- 三处导入提示现已齐全：
  1. 同名建筑物 → 「覆盖更新 / 保留现有 / 取消导入」三选一；
  2. 同一文件（按内容 SHA-256 比对）二次导入 → 「已导入过，是否覆盖」；
  3. 解析不到任何建筑（Placemark）→ 给出原因提示。

### 二、查询/筛选圈选修复与调整
- 0 个符合 → 弹窗提示「没有符合条件的建筑」并保留筛选面板（便于就地调整）。
- 1 个符合 → 立即 `flyTo` 跳转到该建筑物。
- 多个符合 → 倒水滴高亮标记 + **绿色虚线圈**（主题绿 `#2e8b57`，虚线 `7,8`）刚好罩住全部命中建筑，平滑 `fitBounds` 飞入显示整圈（圈线由蓝改绿，与 App 主题一致）。
- 无结果、导入异常等提示统一改用 `ask()`。

### 三、一致性
- 圈选虚线圈由蓝改绿；所有弹窗走统一 `ask()` 与 CSS 变量，风格、背景、色彩、文字全 App 一致。
- 应用内「版本变更」新增 v3.23 记录。

## v3.24（2026-08-19）真机反馈修复（查询圈选 + 类型规范化）

> 按真机测试反馈修复「主界面查询菜单不圈选」「建筑物类型出现乱字段」两类问题，未删除任何原有功能/菜单。

### 一、主界面「查询」菜单圈选补齐
- **原状**：主界面「查询」菜单仅聚焦顶部搜索框，输入关键词后无「确认」动作，不圈选、不定位、不提示。
- **修复**：顶栏「🔍 查询」按钮与搜索框回车键 = 查询确认（`window.doQueryConfirm`），与筛选同一套结果处理：
  1. 0 个符合 → 弹窗提示「没有符合条件的建筑」并保留关键词与搜索框；
  2. 1 个符合 → 立即 `flyTo` 定位到该建筑物；
  3. 多个符合 → 倒水滴高亮标记 + **绿色虚线圈**（主题绿 `#2e8b57`）刚好罩住全部 + 平滑 `fitBounds` 显示整圈 + 居中「命中 N 个」徽标。
- 实时匹配区、防抖渲染等既有机制不变，查询与筛选共用 `passFilter` 条件集。

### 二、筛选圈改浅蓝、查询圈绿色（双圈区分）
- `showFilterResult(matched, color)` 新增颜色参数，`FILTER_CIRCLE_COLORS` 定义两套配色：
  - `green`（查询）：`#2e8b57` 主题绿；
  - `blue`（筛选）：`#4aa3e0` 浅蓝。
- 筛选「确认」多结果 → 浅蓝色虚线圈；查询「确认」多结果 → 绿色虚线圈。动画（由内向外展开 + 行进蚂蚁描边）两色通用。

### 三、建筑物类型规范化
- **乱因**：类型列表此前由数据 `btype` 去重动态生成，导致 `西田各庄段引渠`、`技术指标`、`挖填方统计表`、`进水闸 部分缺少经纬度` 等非类型字段混入「建筑物类型」。

## 2026-08-24 照片性能与老 WebView 兼容性大迭代（v3.30.1 → v3.30.3）

> 本日完成「照片导入可靠性 + 照片性能 + 老设备兼容」三轮迭代，三产品（水利/感知/古建）四端（APK/UOS/Win/Apple）同步升 .1/.2/.3 系列。下面对水利一张图（母版）记录变更，派生 APP 同源对齐。

### 一、安卓 ZIP 照片导入「显示为 0」根因修复（v3.30.1）
- **现象**：批量导入含中文文件名照片 ZIP（如水印中文名），点确定后导入结果「照片显示为 0」。
- **双因**：① ZIP 条目名中文乱码（主因）——`ZipInputStream` 默认按 UTF-8/平台编码解码，7-Zip/Windows 打的含中文名 ZIP 多用 GBK/GB18030，名被乱码化 → 扩展名 `.jpg` 匹配失败 → 抽到 0 张；② 文件夹层级只取首段（次因）——原 `folder = n.substring(0, n.indexOf("/"))` 丢弃嵌套「建筑物」层 → 智能匹配按文件夹名匹配时丢失关键层。
- **根因修复**：`LargeFileManager.unzipImages` 改 `ZipFile(File, Charset)` 显式指定字符集 + `detectZipCharset()` 依次尝试 UTF-8→GBK→GB18030（按是否出现 Unicode 替换符判定）；`folder` 改取完整相对目录 `n.substring(0, n.lastIndexOf("/"))`。三端（水利/感知/古建）同源同步。
- **验证**：三端 `javac -cp android-34.jar` 编译通过；DEX 确认含 GBK/GB18030 字符串；APK 门禁全过。

### 二、两个真实 bug 修复（v3.30.2）
- **Bug A（对勾丢失）**：添加建筑物选照片后 名称/管理所/管理站 右侧「对勾」丢失。根因：「对勾」是 WebView 自动填充标识（非代码 CSS），`fPhotos.onchange` 内 `openEdit(b)` 整体重建 `editBody.innerHTML` 销毁 input.f → 新 input.value 一致但 WebView 未识别。修复：抽 `renderPhotoGrid/buildPhotosHtml/bindPhotoCardEvents`，`fPhotos.onchange` 改用 `renderPhotoGrid()` 只刷 `phGrid` 子树、**保留 input.f DOM**。三产品源/原生壳/归档 win 共 21 份同步。
- **Bug B（ambiguous 保存 0 张）**：ZIP 导入有 ambiguous 待确认项时，点确认保存 0 张。根因：`finishPhotoMatch` 在把 ambBox/dupBox/unmbBox 写入 DOM **之前**就调用了 `maybeCleanInbox()`（函数上方注释说「此处不立即 cleanInbox」但函数体却调了 → 注释与代码矛盾型 bug），三个 `getElementById("ambBox")` 守卫全 null 失效 → `cleanInbox()` 删光 `inbox/uz_*` 临时目录 → 确认时 `linkPhoto(a.it.path)` 找不到文件返回 "" → 0 张。修复：删除该错误调用，清理交还 `confirmAmbiguous/confirmUnmatched/dupOverwrite` 各自末尾（DOM 写入后才调，时机正确）。有 ambiguous 项时 100% 必现；全 auto 匹配不触发（古建用内存守卫 `__dupBlocks.length`，时序天然正确，此 bug 不存在）。
- **验证**：`node --check` 14 份主文件全过；6 份关键文件确认 `fPhotos.onchange`→`renderPhotoGrid()`、`finishPhotoMatch` 内 `maybeCleanInbox()` 已删。

### 三、照片性能三件套 + 老 WebView 兼容（v3.30.3）
- **性能根因**：500+ 建筑、每张 ~7M 原图。①筛选「有照片/无照片」卡死——`showFilterResult()` 为每个命中建筑**立即** `bindPopup(popupHtml(b))`，`popupHtml` 内 `photoSrc(p)` 同步调原生 `thumbPhoto(720)` 解码 7M 原图 → 同步大 IO 阻塞主线程；②`thumbPhoto` 无持久缓存，每次重新解码；③导入链路全部原样落盘不压缩（500×7M≈3.5GB+）。
- **三件套落地**：①筛选/查询高亮 marker popup 改**函数式懒构造**（卡顿根因消除）；②显示改 `ensureThumb(320)` 持久化缩略图（`.thumbs/<size>/` 缓存，首次生成后永久复用）；③导入压缩：`>1.5M` 大图（zip 批量/ovkmz/单张添加/巡视）弹窗选压缩目标（200K/500K/1M/不压缩，默认 500K），原生 4 并发压缩带进度，只存压缩版（删原图前明确提示）。
- **ovobj / obj 奥维坐标导入导出**：独立 `ovobj_bridge.js`（纯函数，含 parse/build Ovobj·Obj + import/export/merge），三产品 index.html 在 app.js 前引入；菜单「传输与共享」组加 [导入ovobj][导出ovobj·实验][导入obj坐标][导出obj坐标]。安卓端 `MainActivity`+`LargeFileManager` 新增 `readFileBase64(path)` 桥供 JS 解析二进制 ovobj。导入 ovobj/obj + 导出 obj 可靠；导出 ovobj 为实验性（名称不等长会字段错位），建议用 obj 文本导出。

- **版本升 .3**：水利 3.30.3(code33)/感知 1.6.3(code12)/古建 1.8.3(code12)；4 份 app.js APP_VERSION+buildDate、4 份 version.json 全对齐（build_apk.sh 门禁自动同步 manifest）。

### 七、关键教训（沉淀）
