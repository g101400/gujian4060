## 1 系统概述

本应用为纯前端 Android WebView 应用，无后端服务器。采用 HTML5 + JavaScript + Leaflet 地图库实现，打包为离线 APK。

### 1.1 技术栈
| 层级 | 技术 |
|------|------|
| 容器 | Android WebView (Chrome 内核) |
| 前端框架 | 原生 JavaScript (IIFE 模块) |
| 地图引擎 | Leaflet 1.x |
| 底图服务 | 天地图 API（CGCS2000） |
| 压缩/解压 | JSZip |
| 数据存储 | localStorage |
| 打包工具 | aapt2 + d8 + zipalign + apksigner |

## 3 数据流设计

### 3.1 数据加载流程
```
APK 内 data.js (初始数据)
    ↓
window.SHUILI_DATA
    ↓
load() → 检查 localStorage
    ↓               ↓
  有数据           无数据
    ↓               ↓
  使用 LS        使用嵌入数据
    ↓
  BUILDINGS[]
    ↓
  render() → 地图标记/线
```

### 3.2 导入流程
```
用户选 .ovkmz 文件
    ↓
JSZip.loadAsync
    ↓
解析 doc.kml (DOMParser)
    ↓
提取 Placemark (name, desc, coords, photos)
    ↓
按 name+坐标 合并进 BUILDINGS
    ↓
save() → localStorage
    ↓
render()
```

### 3.3 导出流程
```
BUILDINGS[]
    ↓
按 office/chan/btype 组织 Folder 层级
    ↓
生成 KML XML
    ↓
JSZip 打包 (doc.kml + ovatta/*.jpg)
    ↓
Android.saveBlob() → Download/水利工程一张图/
```

## 5 安全设计

- 所有用户输入经 `esc()` HTML 转义，防 XSS
- 文件选择仅接受 `.ovkmz/.kmz/.kml` 和 `image/*`
- 导出文件名固定格式，不含用户输入的特殊字符
- localStorage 数据仅本机存储，不外传
- 天地图 Token 为公开浏览器端 Token，不涉及敏感信息

---

## 6 性能设计

- 标记使用 `L.divIcon` + 内联 SVG，避免 HTTP 请求
- 照片初始数据用相对路径（离线可用），新增照片存 base64
- 筛选时仅渲染匹配项，减少 DOM 操作
- 导出使用 Web Worker 风格的 Promise 链，避免阻塞 UI

## v3.7（2026-08-15）优化迭代

> 本次按用户自查清单对「水利工程基础信息一张图」做体验与能力优化，未删除任何原有功能/菜单。

### 一、菜单图标与筛选图标（Req 1）
- 所有菜单图标统一改为**圆形色块**（主色-浅底白字），醒目且风格一致。
- 筛选图标由 `🔎` 改为 `🎚️`，与查询 `🔍` 明显区分（原两者均为放大镜，易混淆）。

### 二、筛选实时计数 + 结果框选（Req 2）
- 筛选弹层顶部新增**实时计数条**「当前符合条件：N 个建筑」，每勾选/取消一个芯片即时刷新。
- 点击「确认」后：
  - 0 条 → 提示「没有符合条件的选项」；
  - 1 条 → 立即定位该建筑物（沿用原逻辑）；
  - 多条 → 每个命中建筑替换为**倒水滴高亮标记**（琥珀色、尖端朝上），并以**蓝色虚线圈**（`#1e6fbf`，虚线 `7,8`）刚好罩住全部命中建筑，自动 `fitBounds` 适配视图。

### 三、批量导入照片（Req 3）
- 入口图标保持醒目；新增**来源选择**：本地文件 / 百度网盘 / 夸克网盘。
- 压缩包格式支持 **ZIP** 与 **7z/RAR**（原生 `unzipImages` 解压；7z/RAR 若原生不支持会提示改用 ZIP）。
- 网盘导入调用原生 `netdiskPick`（若未连接网盘账号则给出明确提示，请先用本地导入）。

### 四、导出照片（Req 4）
- 导出对话框可选：**范围**（全部合并 / 按管理所单独）、**格式**（ZIP / 7z）、**目标**（本地下载 / 百度网盘 / 夸克网盘 / 分享微信 / 飞书 / QQ）。
- 压缩包按管理所命名与分文件夹；新增原生 `shareFile` + `ShareProvider`，**分享到微信/飞书/QQ 真实可用**（以 content:// 规避 Android 7+ 的 file:// 限制）。
- 7z 格式在当前原生打包未支持时回退为 ZIP 并提示。

### 五、智能匹配确认（Req 4 智能匹配）
- 多匹配确认弹窗**默认勾选最匹配项**，并标注**置信度**（高匹配 / 较可能 / 待确认）与**推断范围**（管理所 / 类型），用户可一键确认或改选。

### 六、风格统一（Req 3）
- 顶栏/弹层头渐变、进度条、悬浮按钮等内联色统一引用 `:root` CSS 变量；刷新《07_APP风格色彩字体搭配》。
- 查询/筛选保持顶栏显眼；每页保留「退出本页」；三击空白处仍可呼出主菜单。

## v3.24（2026-08-19）优化迭代（查询圈选 + 类型规范化）
### 一、主界面查询确认补齐（Req：查询与筛选结果处理对齐）
- 顶栏「🔍 查询」按钮与搜索框回车 = 查询确认 `doQueryConfirm()`，与筛选「确认」共用结果处理：0 个符合弹窗提示并保留关键词；1 个符合立即 flyTo 定位；多个符合倒水滴高亮 + 虚线圈罩全部 + 平滑 fitBounds 显示整圈。

### 二、查询/筛选双圈颜色区分
- `showFilterResult(matched, color)` 支持颜色参数：查询多结果 = 绿色虚线圈（#2e8b57），筛选多结果 = 浅蓝色虚线圈（#4aa3e0）；动画（展开 + 行进蚂蚁）两色通用。

### 三、建筑物类型规范化（Req：类型字段干净）
- 引入 `CANONICAL_TYPES` 规范清单 + `ALWAYS_TYPES`（泵站/溢洪道始终展示）+ `canonicalTypes()`，主界面图例、筛选「建筑物类型」、编辑表单类型下拉统一使用。
- 移除被误当类型的字段（西田各庄段引渠 / 技术指标 / 挖填方统计表 / 进水闸 部分缺少经纬度 等）的分类显示；不删除任何建筑；编辑历史脏类型建筑时原值仍可选，避免静默改写。
