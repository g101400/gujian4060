# 版本变更记录 v3.48 / v1.24 / v3.6（2026-09-01）

## 一、本版背景

v3.47 完成了「统信 UOS 纯浏览器壳 + 四架构 deb」「Win WebView2 userDataFolder 权限根治」等收敛，但发版后真机复现一个**致命回归**：水利一张图（安卓/统信/Win/iOS 全平台）打开即崩，**所有菜单点击都报「运行错误：Script error. @0:0」**。

根因定位：`data.js` 中 `window.SHUILI_DATA` 数组在 `b103`→`b104` 两条记录之间**缺失一个逗号**（09-01 坐标更新脚本替换时丢失），导致整个 JSON 字面量解析失败（`Unexpected token '{'` @43923）。`app.js` 读取 `SHUILI_DATA` 得到 `BUILDINGS = undefined`，App 初始化阶段即抛异常，所有依赖 `BUILDINGS` 的菜单/页面在 WebView 中统一报 script error。

本版为**纯修复 + 全平台重建版**：不删除任何已有功能/菜单，按「水利 v3.48 / 感知 v1.24 / 古建 v3.6」同期发版，四平台 + 微信小程序同步。

三图核心实体差异化保持不变：**水利 = 水工建筑物（557 条）**、**感知 = 感知设备（1125 条）**、**古建 = 古建景点（1032 条）**；水利/感知为内部应用（AI 默认关），古建为公共受众（AI 默认开）。

## 二、本版核心改动

### F1 致命修复：data.js 缺逗号导致全 App script error（水利，全平台）

- 根因：`SHUILI_DATA` 数组 `b103` 与 `b104` 之间缺失逗号（`"lat": 40.336104} {"id": "b104"`），JSON 字面量非法 → `window.SHUILI_DATA` 解析失败 → `BUILDINGS` 未定义 → App 初始化即崩 → 所有菜单 script error。
- 修复：`fix_data_comma.py` 对全部活动水利 webroot（canonical `shuili-v329/assets`、mirror `water-v329/assets`、`win-water-webview2/webroot`、`publish_win_water/webroot`、`uos-water-pyqt6/webroot`、`aowwei_app/webroot_shuili`）补回逗号；修复后 `JSON.parse` 全部通过、条目数 = 557。
- 门禁升级：改 `data.js` 后必须 `node --check` + `JSON.parse(SHUILI_DATA)` 校验（557 条），否则拒收——根治「编辑 data.js 即可能整 App 崩」的隐性雷。
- 重建：全部水利包从修复后源码重建（APK + mips64el/loongarch64/arm64/amd64 四架构 deb + MSI + EXE + iOS PWA），并逐一抽取 `data.js` 核验 `b103_BAD=False` / 557 条。

### F2 导出建筑物表格 / 导出照片 — 执行级验证加固（三端共用）

- 旧 `verify_threemap_harness.js` 沙盒对「应用内未定义函数」返回 noop，**无法捕获运行时 `ReferenceError`**（即 WebView 实际报的 script error）。
- 新增 `verify_export_runtime.js` 忠实沙盒（不掩码未定义全局），按浏览器同序加载 `data.js + ovobj_bridge.js + app.js`，实际调用 `exportTable / openExportPhotos / doExportTable / doExportPhotos`，断言不抛错。
- 验证结果：水利/感知 `doExportTable()` / `doExportPhotos()` 全部 PASS（无 script error）；古建走自有 `exportTable` CSV / `exportJson` / `exportOvkmz`，同源同步已确认。

### F3 约束⑤ 古建「退出当前页面」按钮核查

- 旧审计按字面「退出」字符串计数，误判古建仅 4 处、存在缺口。
- 核查结论：古建 `openSheet(id)`（app.js:807）已自动注入「✕ 退出本页」foot（`ensureSheetFoot`，与水利 app.js:1582 同源），被 22 处页面调用；三击空白 handler（pointerdown，app.js:2282-2311）已落地。
- 处置：**不改动** gujian app.js（避免引入新的 script error 回归），在文档中明确约束⑤已在古建满足。

### F4 约束②③④ 三端四平台同步 + 小程序基线

- 水利 v3.46→v3.48 / 感知 v1.22→v1.24 / 古建 v3.4→v3.6 同源收敛，功能不删不减。
- `sync_all_mirrors.py --check` 全镜像一致（EXIT=0）；`sync_weapp_version.py` 小程序基线对齐 v3.48（幂等）。
- UOS deb 四架构 × 3 端 = 12 包，全部通过 `verify_myml_ar.py` 门禁（ar 头空格填充 / mode 100644 / tar.xz，不过不交付）。
- Win MSI/EXE 出包前强制校验 exe 含 `GetWebView2DataFolder` 修复标记 + webroot `version.json` 匹配，缺失直接拒包。

### F5 约束⑦ 智能查询「进一步操作」智能处理

- v3.46 已实现（ai_module.js）：AI 结果底部给出「进一步操作」提示；关键词 chip 单击复制到查询框、双击自动回填并触发查询（`q("qInput").value=v; runQuery()`），兼容老 WebView `execCommand` 回退。本版同源同步，无需新增开发。

### F6 需求七补全：普通智能查询后「进一步查询」智能建议（单击复制 / 双击回填）

- 背景：用户需求第七要求「智能查询后提示用户进一步的操作，做智能处理——单击复制、双击自动把对应关键词复制到查询框并查询」。v3.46 的 AI 模块（ai_module.js）在 AI 结果底部已给出「进一步操作」，但**普通查询路径**（水利/感知走 `doQueryConfirm` 命中多 → 绿色虚线圈选；古建走 `applyFilterAndJump` 命中多 → 跳第一个）此前没有任何「进一步查询」提示（全局 grep 零匹配）。
- 实现：新增 `renderQueryFurther(matched, kw)`，在查询命中多结果时，从命中结果自身的分类字段统计维度频次（≥2 次）取前 8，生成建议 chips：
  - 维度来源——水利/感知：管理单位/管理站/类型/attrs；古建：省份/城市/类别/年代/级别/attrs（通用三端，不依赖各端筛选面板结构）；
  - **单击** chip → `copyText(q)` 复制「原关键词 + 维度值」组合串到剪贴板，toast「已复制查询关键词（粘贴到查询框按确定即可查询）」；
  - **双击** chip → `window.furtherQuery(q)` 自动回填查询框（`#search` / `#filterText`）并立即触发本端查询（优先 `doQueryConfirm`，古建无该函数则回退 `applyFilterAndJump`）；
  - 建议框自愈合挂在搜索框容器下（`#queryFurther` 不存在则动态创建）。
- 注入：`patch_smart_further_query.py` 纯 Python 字符串替换，幂等（已注入则 SKIP）；向 11 个 webroot 的 `app.js` 注入 helpers + 运行时样式（幂等 `qf-style`），并在 `doQueryConfirm` 命中提示行、`applyFilterAndJump`「已定位唯一匹配项」行后调用 `renderQueryFurther`。
- 验证：`verify_smart_further_query.js` 忠实 Node `vm` 沙盒（真实 load data.js+app.js，禁止 mock 数据），三端均 PASS——生成 chips、单击复制含原关键词、双击调起本端查询函数（水利/感知→`doQueryConfirm`、古建→`applyFilterAndJump`）；`node --check` 11/11 全过。
- 覆盖：三端四平台 + iOS 同源（同一 app.js 注入），本次重建随包分发（见第五章交付物）。
