## 二、建筑物类型增删改（B3 强化）

`orgPanelTypes` 完全实现「可添/可改/可删」+「逐个确认同步受影响建筑」：
- 添加 → 直接 push customTypes 数组 + refresh
- 重命名 → 找出所有 `b.btype === old` 的建筑 → `window.ask("同步建筑物 k/N", ...)` 逐个 confirm
- 删除（仅 custom） → 先 toast 提示受影响数 → 二次确认 → 删除
- 失败兜底：被内置权威类型名（CANNONICAL_TYPES）保护的不可删除

## 五、zip 三级匹配 level-aware（B6 算法升级）

`itemOrgScope` 升级：
- 匹配顺序按 **局 → 处 → 所 → 站 → 段** 层级逐级（zipName 命中即锁定该层）
- 命中后返回 `parentLevel`（该层下一级）供 folder 子匹配用
- folder 拆 `/` 逐段匹配，命中级别应等于 zipName 的 parentLevel（链式下钻）
- 示例：
  - `史山.zip` → 命中 所=史山所 → parentLevel=zhan
  - `京密引水管理处.zip` → 命中 处=京密引水管理处 → parentLevel=suo
  - `京密引水管理处/水库所/IMG_xxx.jpg` → folder 段从所开始匹配到「水库所」
- 兜底：folder 整段或子段未命中时返回 null，按 fname 模糊匹配
