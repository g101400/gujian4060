## 二、核心改动

### E1 知识库导出 md/txt/html 自定义文件名+文件夹（kbExport 重构，三应用同步）

- 由固定 `知识库_域名_日期.fmt` 改为弹窗交互：文件名默认 `知识库_YYYYMMDD.fmt` 可改（自动补后缀），可填保存文件夹。
- 安卓走原生 `window.Android.saveBlobTo(dataUrl, folder, name)` 落 `Download/<folder>/`；Win/统信/网页回退 `<a download>` 系统下载目录并 toast 提示。
- 新增 `kbExportSave / kbToB64 / kbCloseGen`；共享模块 `ai_module.js`（kbExport 在共享模块，三应用 md5 一致）。

### E2 数据脱敏机制修复（本版安全重点）

- **问题**：gh_sync.py 推公开仓时仅排除 `assets/ai_seed.js`，`assets/data.js / kb_building_seed.js` 原样上传——2026-09-05 深夜把 v3.58/v1.34（内部真实种子）同步到公开仓 `shuili-yitu-5090pub` / `ganzhi-yitu-5090pub`，导致真实内部数据进入公开仓历史。
- **修复（机制层）**：gh_sync.py pub 通道新增 demo_replace——`data.js / kb_building_seed.js` 一律用 `*.demo.js` 内容替换后上传；私有仓（int）保持真实数据全量。此后即使本地为内部形态，公开仓也只会收到演示种子。
- **本地现场**：`strip_internal.py --public` 已将 shuili-v329 / perc-v13 assets 切为演示种子（真实数据备份在 `.strip_backup/{shuili,perc}/*.real.bak`，可 `--restore` 还原）。
- **遗留风险（需用户决策）**：公开仓**历史 commit** 仍含真实数据（已发布内容无法用新提交抹除）。当前 main 树本轮已覆盖为演示数据。可选处置：① 公开仓转私有/重建（会断 Release 与 App 内升级基线）；② 保持现状并知悉历史可被访问；③ 联系 GitHub 清历史。App 内升级走 Release，重建后需重发四平台包。
- 本轮发布仅更新**公开仓**（-5090pub ×2 + gujian-travel5090）；**私有仓不动**（内部 3.58/1.34 已发 Release 保持有效，待下轮偶数号 bump 再同步代码与文案）。
