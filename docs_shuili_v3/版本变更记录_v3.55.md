## 二、核心改动

### E1 切片保持语句完整（kb_rag.js `chunkText` + ai_module.js `kbSliceText` 双实现）

- 旧实现的两个截断点已根治：
  - 超长块（>size×1.4）曾直接 `slice(0,size)` **硬切在句中** → 改为「段落→句末标点→逗号级→极端硬切兜底」四级递归，普通文本永远整句收口；
  - 打包时重叠回溯曾把下一片顶到 **size+整句** 超长 → 改为重叠预留预算 `budget = size - s.length - 1`，重叠句放不下就不带重叠，保证片段 ≤ size+overlap。
- 句切分 `splitSentences` 保留标点、不用 lookbehind（旧 WebView 兼容）；`splitClauses` 二级按 ，，、：：切，仅用于超长句。
- 测试 `kb_slice_test.js`（11/11）：句末标点收口、逗号不截断、无标点兜底、内容不丢失、双实现一致。

### E2 保存前先切片再落盘（单一写入口 + 签名缓存）

- `kbSave(o)` 成为知识库唯一写入口：保存前对每个条目执行 `kbSyncChunks`——正文签名（长度+首尾16字符）变化才重切片，切片随条目一起存入 `o.chunks[id]` / `o.chunkSigs[id]`。
- 覆盖路径：kbAdd、文档导入(md/txt/html/json/zip)、网页入库、OCR 外部文件入库、Hermes 沉淀、查询保存、批量写入全部生效；`kbRemove` 同步清理切片。
- 切片含标题行（与 kb_rag `buildIndex` 的 title+body 约定一致）；RAG `addDoc/buildIndex` 优先复用已存切片（`doc.chunks`），重建索引更快且与保存内容一致。
- 收益：切片在**保存时**完成而非仅在检索时，跨端导出/导入的备份自带切片；向量索引与知识库正文永不脱节。
