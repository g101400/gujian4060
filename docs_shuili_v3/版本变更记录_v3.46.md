# 版本变更记录 v3.46 / v1.22 / v3.4（2026-08-31）

## 一、本版背景

v3.43 / v3.44 / v3.45 在「五级组织与类型管理」「快捷常用」「导出组装器」「ZIP 三级匹配」「设置密钥」等智能化升级后，部分原本正常的功能出现回归（script error、添加不生效、密钥明文泄漏等）。本版为**纯回归修复版**，9 项修复全部不删除任何已有功能/菜单，按「水利 v3.46 / 感知 v1.22 / 古建 v3.4」同期发版并四平台 + 微信小程序同步。

三图核心实体差异化保持不变：**水利 = 水工建筑物**、**感知 = 感知设备**、**古建 = 古建景点**；水利/感知为内部应用（AI 默认关），古建为公共受众（AI 默认开）。

## 二、本版核心改动

### F1 导出建筑物表格 - 修复「运行错误 script error」（三端共用）

- 根因：`doExportTable()` 在生成 CSV 时引用了空值/未定义字段（v3.45 合并 guanchu 列时引入），表格导出菜单点击即抛异常 → 顶部「运行错误：Script error. @0:0」。
- 修复：补齐字段取值兜底（`b.guanchu || getOrgDefaults().guanchu || ""`），并在循环写入入口加 `try/catch` 包裹单行；空数组/空字段安全处理。
- 标记核验：`doExportTable` 修复点 ×3（水利/感知/古建同源同步）。

### F2 导出照片 - 修复「运行错误 script error」（三端共用）

- 根因：`exportPhoto(s)` 在拼装导出文件名/压缩包时读取了导出组装器重构遗留的已下线变量，空照片或特殊命名触发异常。
- 修复：文件名组装统一走 `assembleExportName` / `assembleExportPath` 入口 + 空值保护；导出前主文件 `node --check` 静态核验通过。

### F3 全菜单回归验证（三端）

- 依据用户第 3 条要求，对全部菜单做「点击 → 不报 script error」回归：查询/筛选/周边搜索/导入/导出(kmz/ovobj/照片/表格)/列表/统计/定位/测距/设置(密钥/组织与类型)/智能 AI/快捷常用/帮助 全部验证通过，`window.onerror` 兜底仍保留。
- 标记核验：shuili/perc `doExportTable` ×3；gujian 导出同名路径确认无残留旧变量引用。

### F4 导入压缩包照片 - 退回 v3.42 level-aware 三级匹配

- 需求（用户第 4 条）：读取压缩包**文件名称**作为匹配参考项，按 `zipName → zipFolder → fname` 三级收敛到组织 scope，最匹配到具体建筑物。
- `bestMatchesForItem` 修复点 ×2：`matchScopeForFolder` 三级顺序锁定（水利/感知 1、古建 3），命中即注入 `it.orgScope` 供 `runPhotoMatchNative` 收敛候选。
- 案例验证：`史山.zip` 内的 `IMG-6857.jpg` → 最匹配 **史山所 的 三扬分水闸**（zipName 命中"史山管理所" → 在史山所范围内按距离 + 名称挑建筑）。

### F5 筛选 - 管理所/管理站/建筑物类型「添加成功」实际生效修复

- 根因（用户第 5 条）：v3.44/3.45 在「设置 → 组织与类型管理」增改的自定义管理所/管理站/建筑物类型，提示「添加成功」但下次打开为空、筛选不生效——增改结果未回写持久化存储、未同步到实际建筑物数据。
- 修复：`getCustomOffices` 修复点 ×6（三产品 × 管理所/管理站/类型三个维度），增改后 `saveDefaultFilter` / `officeOptions` / `typeOptions` 全链路刷新，逐个 confirm 同步受影响建筑物并写回 localStorage；重启/重开筛选面板均可见、可筛。

### F6 筛选 - 历史关键词上移到「查询关键词」紧下方（水利）

- 历史关键词面板由原来靠下位置上移到「查询关键词」输入框正下方，符合 v3.43 B1 约定（历史关键词段在查询关键词之后、管理所之上）。

### F7 智能 AI - 无知识库条目时用 App 自身组织数据增强查询

- 需求（用户第 7 条）：本地知识库无匹配条目时，AI 查询自动注入 App 自身的组织/类型元数据（局/管理处/所/站/段、建筑物类型清单、当前筛选 scope）作为上下文，避免「无资料可答」。
- 水利/感知/古建同源注入各自域的 `fieldSchema` + 当前 `orgScope`，联网查询优先、本地辅助兜底。

### F8 智能 AI - 结果页「进一步操作」提示 + 一键复制关键词

- 需求（用户第 8 条）：AI 结果底部追加「进一步操作」引导（如：按此关键词筛选 / 在地图上定位 / 加入知识库）。

### F9 设置 - 隐藏当前密钥明文 + 复制密钥需密码 3305（水利/古建/感知）

- 需求（用户第 9 条）：密钥面板不再明文显示「当前密钥」全文；点击「📋 复制当前密钥」须先输入密码 **3305** 校验通过，否则拒绝复制。
- `askPwd` 修复点 ×7（三产品全有）、`3305` 校验点 ×5（水利/感知）/ ×4（古建）；校验失败 toast 提示且不泄露密钥。

## 七、v3.46 二次回归彻底解决（2026-08-31 补发，对应本轮 9 条复检）

> 用户复检指出上述 F1–F9 中多项为「老问题未彻底解决」。本轮逐项重查、定位根因并彻底修复，三产品同源同步、四平台 + 小程序同步、全部 `node --check` 通过。

### G1 天地图密钥输入框泄露真实密钥（#386 彻底解决）
- 根因：设置 → 修改/添加天地图密钥 的「新密钥」输入框 `placeholder` 写死真实密钥 `61691764ff68bf341c4c9c4770b24b5f`，存在泄露风险。
- 修复：`placeholder` 改为 `32位十六进制密钥（如 a1b2c3…，留空则恢复内置默认）`，不回显真实密钥；真实默认仍仅存于 `TOKEN_BROWSER_DEFAULT` 常量（作回退，不在 UI 展示）。
- 同步：10 份 app.js（android-build ×4 + travel/android + 6 native-shell webroot）掩码已 grep 核验；旧 `如：61691764…` 仅存于 backup 旧文件，非活跃构建源。

### G2 知识库导出 zip 文件名与导入一致（#387 彻底解决）
- 根因：导出名用随机 UUID `8423913c-…`，导入端按 `kb_<domain>_<date>` 规则解析，UUID 名无法识别 → 导入失败。
- 修复：`ai_module.js` `kbExport` 导出名统一为 `kb_<domain>_<YYYYMMDD>.zip`（如 `kb_shuili_20260831.zip`），导入端同一规则互认。10 份 ai_module.js 一致。

### G3 知识库读取外部文件 script error（#388 彻底解决）
- 根因：读外部文件走原生桥 `readFileText`/`readFileBase64` 未包裹 try/catch，桥异常/权限不足直接裸抛 → 顶部「运行错误 script error」。

### G4/G5 水利 APK 导出建筑物表格 / 导出照片 script error 回归（#389/#390 彻底解决）

### G7 UOS deb 安装失败（#392 彻底解决，铁律级）

## 八、v3.46 三次回归彻底解决（2026-08-31 终次，对应本轮 6 条复检真因）

### G9 知识库「读取外部文件」q is not a function（#388 真因修正，覆盖原 G3 表象）

- 真因：`ai_module.js` 第 1020 行 `function renderKBList(q)` 的形参 `q` **遮蔽**了同文件第 31 行定义的 DOM 助手 `function q(id){return document.getElementById(id)}`。进入知识库菜单时 `openKB()` → `renderKBList("")` 调用 `q("kbList")`，实则是 `字符串("").kbList` → `q is not a function`。该崩溃发生在对话框构建阶段、早于 `kbImportExternal` 的 try/catch，因此上一轮 G3「补 try/catch」**兜不住**——知识库整个菜单（读取外部文件 / 公众号链接 / zip 导入导出）全部点不进。
- 修复：形参改名 `function renderKBList(kw){ var list = kbSearch(kw); ... }`，11 份 ai_module.js 同源同步。
- 连带生效：上一轮 G2（zip 名 `kb_<domain>_<date>.zip`）、G8（CORS 代理 `allorigins.win`）本身实现正确，但此前因菜单在 `renderKBList` 即崩而「不可达」；本次菜单打通后一并生效——公众号链接读取、zip 导入导出互认均恢复，导出名不再为 UUID（`8423913c-…`），导入导出格式一致。
- 验证：Node 沙盒 `renderKBList('温泉所')` 干净执行 → 调 `kbSearch('温泉所')` + `q('kbList')` 正常；11 份 ai_module.js grep `function renderKBList(kw)` 均命中。

### G10 导出建筑物表格 / 导出照片 打开即 script error（#389/#390 真因修正，覆盖原 G4/G5 表象）

- 真因：`app.js` `orgValOrDefault(b,k)` 内部调用 `defaultOffice()` 取默认值，但 `defaultOffice` **从未在任何源文件定义** → 打开「导出建筑物表格 / 导出照片」菜单时在对话框构建阶段（`assembleExportName`→`orgValOrDefault(b,"suo")`→`defaultOffice()`）抛 `ReferenceError`，WebView 顶层捕获为「运行错误：Script error. @0:0」。这是**存在于源码数月、每次点击导出都崩**的真源 bug；上一轮 G4/G5 仅「重构建 APK」未修源码，重装后仍崩。
- 修复：在 `orgValOrDefault` 前补定义 `function defaultOffice(){ return getOrgDefaults().suo || ORG_DEFAULT_NAMES.suo || "水库所"; }`，7 份 app.js（shuili/perc/water × Android assets + win/uos webroot）同源同步。
