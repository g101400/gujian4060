## 二、核心改动

### E1 升级深链修复（upOpenUrl 兜底，四端 app.js + upgrade_funcs.src.js 源）

- 根因：升级菜单「点击下载更新包」是 `<a target=_blank href="百度分享页">`，在安卓 WebView 内加载百度页 → 302 跳转到 `bdnetdisk://` 深链 → WebView 不识别该 scheme → 报 `ERR_UNKNOWN_URL_SCHEME`，升级流程卡死。
- 修复：新增 `upOpenUrl(event, url)` helper——`openExternal`（系统浏览器 / 网盘 App）优先接管打开，`<a>` 点击回落，并 `return false` 阻止 WebView 默认导航；升级菜单的下载入口统一改调 `upOpenUrl`。
- 影响范围：水利/感知/古建三产品 × 四端（APK / Win MSI+EXE / UOS deb / iOS PWA）app.js 全部注入；源 `upgrade_funcs.src.js` 同步，后续 bump 自动携带。
- 验证：`up_test.js` 14/14（合并/覆盖/跨平台/默认名）通过、启动 OK×3、沙箱验证 openExternal 接管成功、不再触发 ERR_UNKNOWN_URL_SCHEME。

## 四、踩坑与铁律（已沉淀 SKILL.md）

- **顺序正则切版本串会互相覆盖**：set_build_versions 双通道切换器按「产品配置块」定位切版本，不得用裸顺序正则（upg 在行尾会定位错块）；切换后必 `grep` 四脚本（bump/build/make_deb/version.json）全量核对。
- **改 make_deb 后必须重跑全部架构**：未重跑的架构会出「文件名 1.34 / 内容 1.33」错位包，`verify_pass.py` 按文件名断言版本可抓出。
- 升级深链铁律：WebView 内任何外链跳转一律走 `upOpenUrl(event,url)`（openExternal 优先 + return false 阻默认导航），禁止裸 `<a target=_blank>` 跳外部 scheme。
