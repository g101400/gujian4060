## 一、修复

### 1. 口令门提示残留具体口令（5）
- 现象：内部版口令框提示仍显示「默认口令即开发者分机号 **3305** · 输错无法进入」。
- 根因：上一轮只清理了写死的字面量，漏掉 `secure_boot.js` 中 `'…分机号 ' + DEV_EXT + ' …'` 这种**变量拼接**；`DEV_EXT="3305"` 运行时仍渲染出来。
- 处理：提示行改为「默认口令即开发者分机号 · 输错无法进入」，**不再拼接 DEV_EXT**（常量本身保留用于校验，代码中仍不出现明文口令）。
- 影响面：水利/感知 `assets/secure_boot.js`、`native-shell/water-ios/secure_boot.js`（iOS 内部加密 PWA 模板）及随镜像同步的 Win/UOS webroot。

### 2. 本地导入/导出误报「非 WiFi 网络」（6）
- 现象：导出全部照片、导入 ovkmz、导出 ovkmz、导出照片 四个**纯本地**操作，也会弹「非 WiFi 网络 / 可能消耗大量流量…」。
- 处理：新增 `confirmLocal(action, bytes, cb)`：
  - `bytes < 100MB` → **不弹窗，直接执行**；
  - `bytes ≥ 100MB` → 弹「**操作提示** / 文件大小为 **XX MB**，耗时较长，是否继续？」。
  - 体积估算：照片类按 `数量 × 2.5MB`；导入 ovkmz 走原生 `window.Android.fileSize(path)` 取真实大小。
- 真网络操作（手机互传·从服务端下载）**保留**「非 WiFi 网络」警告。

### 3. 「管理处」两面不一致（8/9）
- 现象：筛选栏「管理处」有 5 个处；「设置 → 组织与类型管理 → 管理处」只有 1 个（京密引水管理处），且其余 4 个无法删除/改名。
- 根因：`orgStore()` 对「所」做了权威清单兜底合并（`CANONICAL_OFFICES`），对「管理处」**没有**等价合并 → 另 4 个处从未进入 `org_levels.guanchu`。
- 处理：
  1. `orgStore()` 对 `guanchu` 首次初始化时补齐 `CANONICAL_GUANCHU`（5 个处）；**用户一旦自行增删改，则尊重用户清单、不再回灌**，保证删除/改名真实生效（区别于 suo 的强制回灌）。
  2. `guanchuOptions()` 改为与 `orgStore().guanchu` **同源**（不再单方面硬塞常量），筛选栏与管理面板一一对应。
  3. 筛选栏「管理处」区段新增 **＋添加 / ✎改名** 按钮（与所/站一致），改名会提示受影响的建筑物数量并可一键同步。
  4. `FIELD_ALIAS` 修正：`管理处 / 所属管理处` 从 `office` 别名中移除，新增 `guanchu`（及 `ju`）独立别名 —— 根治「导入含『管理处』列被写进管理所」的串字段问题。

### 4. 公共模块回灌（2，感知/古建受益）
- `kb_rag.js` / `ai_module.js` / `ovobj_bridge.js` 从水利回灌到感知与古建。
- 修复「知识库整句切片」与「导出 ovobj 文件名可编辑」在感知/古建**实际未落地**（历史版本变更与对照单曾标 ✅，属虚假通过）。
- `sync_all_mirrors.py` 新增**跨产品公共模块 md5 门禁**（7 个共享模块必须三端字节一致），防止再次分叉。
