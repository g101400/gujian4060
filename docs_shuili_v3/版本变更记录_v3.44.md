## 一、本次修复的历史 cp 失误（perc v1.20）

过去 cp 失误让 perc 工程的 **APPNAME / LS_KEY / data.js / AIModule.init** 全部遗物沿用 shuili，导致：
- perc 智能查询 placeholder 显示「龚庄子进水闸」（水利语，而非感知语）
- perc 加载不到 `window.PERCEPTION_DATA`（一直走 `window.SHUILI_DATA` 兜底，永远无数据）
- perc 与 shuili 共用 localStorage key `shuili_map_v2`，两工程数据互相覆盖
- perc AIModule.init 的 domain 用 "shuili"，localStorage 命名空间冲突

| 项 | 修复前 | 修复后（v1.20）|
|---|---|---|
| APPNAME | 水利工程基础信息一张图 | **水利感知项目一张图** |
| LS_KEY | shuili_map_v2 | **perc_map_v2** |
| 数据源 | `window.SHUILI_DATA \|\| []` | **`window.PERCEPTION_DATA \|\| window.SHUILI_DATA \|\| []`** |
| AIModule.domain | shuili | **perc** |
| AIModule.appName | 水利工程基础信息一张图 | **水利感知项目一张图** |
| AIModule.fieldSchema | office/station/btype/chan | **+ subsystem**（设备子系统：视频监控/雨水情/大坝安全/地下水源）|
| UOS webroot | uos-pyqt6 内部 app.js 是水利 | **替换为 perc 完整 webroot（含 PERCEPTION_DATA data.js）** |

## 二、古建 v3.2 智能化升级（公共受众场景）

古建当前 v3.1 没有任何 v3.40-v3.43 智能化升级。本次完全重做：

### ① 古建 5 级组织（景区层级）
| 水利（JU/GUANCHU/SUO/ZHAN/DUAN）| 古建（SPOT/AREA/SUB/POINT/TAG）|
|---|---|
| 局 | **景区**（颐和园/故宫/敦煌莫高窟）|
| 管理处 | **园区**（佛香阁景区/外朝）|
| 管理所 | **子景点**（佛香阁/仁寿殿/万寿山）|
| 管理站 | **打卡位**（主入口/山顶/碑亭）|
| 段 | **标签**（UNESCO/5A/皇家园林/世界遗产）|

完全复用水利 `getOrgDefaults()` + `bJu/bGuanChu/bZhan/bDuan` 模式：
```js
function _v32_bs(b, k) {
  if (k === "spot")  return b.spot  || _v32_gOrgDefaults().spot  || "";
  if (k === "area")  return b.area  || _v32_gOrgDefaults().area  || "";
  if (k === "sub")   return b.sub   || _v32_gOrgDefaults().sub   || "";
  if (k === "point") return b.point || _v32_gOrgDefaults().point || "";
  if (k === "tag")   return Array.isArray(b.tags) ? b.tags.join("、") : (b.tag || _v32_gOrgDefaults().tag || "");
}
```

### ② 17 类古建专属 CANONICAL_TYPES
`古塔、寺庙、城墙、古桥、园林、陵墓、书院、会馆、故居、古街、楼阁、亭台、坛庙、宫殿、石窟、衙署、其他` ——完全替换水利的工程类类型（节制闸/进水闸/泄洪闸等）。

### ③ 快捷常用 ⭐ 菜单组（v3.42 同步 + 古建改造）
- 直接复用水利 `menu-fav` 星标机制
- 古建专用收藏项：`🛰️ 导入 ovobj`、`📦 导出 ovkmz`、`📸 打卡`、`🛤️ 打卡路线`、`📏 测距`、`🗺️ 底图切换`、`⌂ 放回收藏窗口` 等
- 通过 `stopPropagation()` + `preventDefault()` 严格隔离星标点击 vs 菜单项点击
- 收藏结果在「拍照打卡」之前显示为独立分组

### ④ 历史关键词可折叠面板（B1 古建版）
- filter 区顶部新增「🔖 历史关键词」可折叠
- 与水利完全相同的体验，但古建关键词不与 shuili 共用（key=`gujian_query_history_v32`）

### ⑤ 周边搜索 nbtype chip（B4 古建版）
- 包装原 `nearbySearch`，注入 `nbtype_v32` chip 渲染到筛选区
- 点击 `stopPropagation` 防误触模式按钮
- 与水利同款 toast 反馈

### ⑥ ZIP 三级匹配古建版
按 `spot → area → sub → point → tag` 链式下钻，覆盖原 v3.42 的「按局处所站段」匹配：
```js
function _v32_matchOrgInToken(token, levels) {
  for each level in levels:
    var arr = [def.spot].concat((def.spot||"").split(/[、,，]/));
    if (t.indexOf(v.toLowerCase()) >= 0) {
      return { level, value: v, parentLevel: next_level };
    }

```
调用链 `matchOrgInToken(zipName) → matchOrgInToken(folder 子段) → matchOrgInToken(fname)`。

### ⑦ AI 系统提示词注入古建文物助手分支
联网核实公开文物，优先引用权威来源：
```
你是文物/古建知识助手。用户会提供某处古建的名称与现有资料，并可能要求联网核实公开信息。
回答时优先引用权威来源（文物局/省级文物局/UNESCO/世界遗产委员会官网）；
若用户提供的数据与公开资料冲突，请明确标注差异，不可妄断。
结构建议：①年代/级别 ②主要建筑特征 ③历史沿革 ④参考资料。
```
本地资料兜底：禁止编造朝代/级别/坐标/尺寸，仅补充通俗介绍/参观建议/相似对比。

## 七、已知限制

1. **古建 v3.2 增量更新**：v3.1 用户的 localStorage（无 gujian_org_defaults / 无 favorites）需手动进设置启用，或下次进设置面板时一键同步
2. **perc v1.20 数据迁移**：v1.19 用户（直接用 `shuili_map_v2` key）首次升级后看到的可能是水利数据，建议操作：① 设置 → 「恢复初始数据」可加载 1125 条感知设备；② 重新筛选即可
3. **古建 v3.2 快捷常用**：与水利 v3.42 快捷常用数据互不影响（key 隔离：gujian_favorites_v32 vs shuili_favorites_v32）
4. **AI 联网古建仍需用户手动开启一次**：虽然默认 kOnline=true，但首次安装后需在「智能 AI 设置」里点一次"开启联网"才会真正联网（默认行为）
5. **小程序 jingyin baseline 字符串**：仅作为跨端对齐指示，不影响功能
