# 水利工程一张图 · 开发踩过的那些坑

做一款离线地图 App，表面风平浪静，背后全是坑。这里把开发「水利工程一张图」时真实踩过的坑摊开讲——每个都附带**现象、根因、教训**，希望能帮到同样在做前端 / 移动端地图应用的你。

---

## 1. data.js 缺一个逗号，全 App 打开即崩
- **现象**：v3.47 发版后，水利一张图全平台打开即崩，所有菜单点击都报「运行错误：Script error. @0:0」。
- **根因**：`SHUILI_DATA` 数组两条记录之间缺失一个逗号（坐标更新脚本替换时丢失），整个 JSON 字面量解析失败，`BUILDINGS` 变成 `undefined`，初始化阶段就抛异常。
- **教训**：改数据文件必须有门禁——新增 `node --check` + `JSON.parse` 校验（557 条），否则不收。

## 2. 字符串里没转义的双引号，白屏假死
- **现象**：v3.1 安装后白屏/假死，地图、菜单、按钮全失效。
- **根因**：提示字符串内含未转义的双引号，导致 `app.js` 解析阶段 `SyntaxError`，整个 IIFE 不执行，所有初始化都没跑。
- **教训**：字符串里出现引号必须转义；并加全局 `onerror` 兜底，避免「无提示假死」。

## 3. 打开导出菜单就崩：一个从未定义的函数
- **现象**：点「导出建筑物表格 / 导出照片」直接 script error。
- **根因**：`orgValOrDefault` 调用了 `defaultOffice()`，但该函数**数月来从未在任何源文件定义**，点击导出时必抛 `ReferenceError`。
- **教训**：这种「源码真源 bug」靠重构建 APK 是修不好的，必须读源码定位；用 Node 沙盒实际调用函数做执行级验证，而不是只做语法检查。

## 4. 形参遮蔽 DOM 助手：`q is not a function`
- **现象**：知识库菜单点不进，整页 script error。
- **根因**：`ai_module.js` 里 `function renderKBList(q)` 的形参 `q` 遮蔽了同文件 `function q(id){return getElementById(id)}`，调用 `q("kbList")` 实为 `字符串.kbList`。
- **教训**：避免用 `q` 这类极短名做函数形参；同名遮蔽是隐蔽雷。

## 5. 老 WebView 缺 ES6：部分功能崩、部分正常
- **现象**：用户装新包仍报 script error，但有的功能正常。
- **根因**：系统 WebView 未更新（Chrome 37），缺 `Array.find / Object.assign / TextDecoder` 等 ES6 API，恰好用到这些的功能崩。
- **教训**：在 `app.js` / 桥文件顶部统一补 polyfill（含手写 utf8 兜底），老设备才稳。

## 6. 统信 UOS deb 安装失败：目录条目与 ar 大小
- **现象**：龙芯安装报「无法创建 …/webroot/ai_module.js.dpkg-new：没有那个文件或目录」「deb 文件损坏」。
- **根因**：纯 Python 构造 tar 只写文件、未声明父目录条目；`ar` 成员大小未按偶数补齐，部分解包器校验失败。
- **教训**：写文件前回退生成全部祖先目录 `DIRTYPE` 条目；`ar` 头空格填充 + mode 100644 + 大小补齐；并用 `verify_myml_ar.py` 门禁锁死。

## 7. Win MSI/EXE 无权限：userDataFolder 指向错目录
- **现象**：安装后 Win 端无权限打不开。
- **根因**：WebView2 的 `userDataFolder` 指向无权限目录（E_ACCESSDENIED）。
- **教训**：出包前强制校验 exe 含 `GetWebView2DataFolder` 修复标记，缺失直接拒包。

## 8. ovobj 导出乱码：`escapeJson` 漏了单引号
- **现象**：个别菜单导入 ovobj 报 script error。
- **根因**：`escapeJson` 只转义双引号，漏了单引号，注入 KML 属性时破坏结构。
- **教训**：JSON 注入到 XML/属性，单双引号都要转义。

## 9. 打包多副本分叉：陈旧副本污染同步门禁
- **现象**：同步检查报「不一致」，陈旧非注入版差点被推回镜像。
- **根因**：构建真相源 `travel/android/assets` 已注入新功能，但某脚本仍把陈旧分叉 `android-build/gujian-v31/assets` 当 canonical。
- **教训**：多副本必须只有一个真相源；同步脚本的 canonical 要与构建流水线（release/build）严格对齐，门禁要嵌进发版脚本阻断，而非只写文档。

## 10. 验证沙盒太「友好」，漏掉运行时错误
- **现象**：旧 harness 对未定义全局返回 noop，导出函数里的 `ReferenceError` 抓不到。
- **根因**：沙盒掩码了未定义全局，掩盖了真实 WebView 报错。
- **教训**：验证要用「忠实沙盒」（不掩码未定义全局，真实 load data.js+bridge+app.js 并调用函数），才能捕获真源 bug。

## 11. 注释与代码矛盾：定时炸弹
- **现象**：ZIP 导入有待确认项时，点确认保存 0 张。
- **根因**：`finishPhotoMatch` 上方注释写「此处不立即 cleanInbox」，函数体却调了它，三个 `getElementById` 守卫全 null 失效。
- **教训**：注释说「不调用」却调用 = 高危信号，必须核对；DOM 守卫清理逻辑要在 innerHTML 写入之后调用。

## 12. ZIP 中文名乱码 + 层级截断
- **现象**：批量导入含中文名照片 ZIP，结果「照片显示为 0」。
- **根因**：ZIP 条目名中文按 UTF-8/平台编码解码，7-Zip 打的含中文名 ZIP 多用 GBK/GB18030；文件夹层级只取首段丢嵌套「建筑物」层。
- **教训**：显式指定字符集 + `detectZipCharset()` 依次尝试，并用完整相对目录。
