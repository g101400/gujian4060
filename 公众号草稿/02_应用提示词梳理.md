# 水利工程一张图 · 应用里的「提示词」都长什么样？

很多用户好奇：水利工程一张图的「智能 AI」到底是怎么问答的？它背后有没有写好的提示词？答案当然是**有**，而且分得很细。本文把应用里真正生效的提示词与种子一次性梳理清楚。

---

## 一、三态系统提示词（systemPrompt）

智能助手的「人设」由 `ai_module.js` 里的 `systemPrompt()` 决定，它按**是否联网**和**应用域**分成三种，避免内部资料被大模型编造。

### 1. 古建 · 联网模式
> 你是文物/古建知识助手。用户会提供某处古建的名称与现有资料，并可能要求联网核实公开信息。请基于可靠的公开知识作答；如不确定请说明。回答用中文，简明有条理。

### 2. 水利 / 感知 · 联网模式
> 你是「水利工程基础信息一张图」的联网查询助手。用户会提供某建筑物/设备的名称与现有资料，可联网核实公开信息（如标准参数、行业规范、厂家、同类工程案例）。**数据组织原则**：本系统采用 5 级组织（局 → 管理处 → 所 → 站 → 段），用户查询时尽量按 5 级层级回答；当用户问『管理处下属多少所/站/段』时，结合组织清单 + 实际数据回答。请基于可靠公开知识作答；如不确定请说明。回答用中文，简明有条理。

### 3. 本地辅助模式（水利 / 感知默认）
> 你是「本系统」的本地数据辅助助手。本系统采用 5 级组织（局 → 管理处 → 所 → 站 → 段），用户问『×下属多少×』时按组织清单回答。本系统的建筑物/设备为内部资料，公开大模型没有其准确数据，禁止编造或臆测任何内部参数与坐标。你只能基于用户提供的本地记录上下文进行分析、补全缺失字段、指出存疑项，不要声称来自外部网络。回答用中文，简明。

**设计要点**：内部资料（水利 / 感知）默认「本地辅助」，明确禁止编造；公共受众（古建）才开放联网核实；三态都强调「5 级组织」概念，让模型能回答组织层级类问题。

## 二、查询框占位示例（三态 placeholder）

搜索框的灰色提示文字也按域区分，引导用户怎么问：

- **古建**：如「颐和园佛香阁的建筑年代与结构特点」
- **感知**：如「北台上液位传感器最近一次监测数据」
- **水利（默认）**：如「龚庄子进水闸的设计流量与结构特点」

这三句话是 `ai_module.js` 里 `CFG.appName.indexOf("古建"/"感知")` 分支通用化生成的，三端共用一份 `ai_module.js`，彻底消除了早前「感知 / 古建还残留龚庄子」的串味问题。

## 三、本地密钥种子（ai_seed.js）

个人模型配置不写进共享源码，而是单独放在 `ai_seed.js`（仅本机 / 私有构建使用）：

```js
window.AI_SEED = {
  apiKey: "sk-or-v1-****",        // 个人 OpenRouter Key
  default: "minimax-m27-free",    // 默认模型
  strategy: { mode: "failover" }  // 限流自动切换下一模型
};
```

内置三个 OpenRouter 免费模型预设：**MiniMax M2.7 / GLM 5.2 / Nemotron 3 Nano Omni**（均 `:free`、OpenAI 兼容），默认 failover 策略，免费模型上游限流时自动切换下一个，避免单模型 429 中断。

> ⚠️ 提醒：`ai_seed.js` 里的 Key 是个人凭证，**请勿公开分享**，也不要提交到共享仓库。

## 四、知识库种子（kb_building_seed.js）

为了让「本地辅助」也有料可答，构建期会预生成知识库种子随包内置：

- 水利 **557** 条 / 感知 **1125** 条 / 古建 **1032** 条；
- 每条含属地 / 朝代 / 级别 / 简介 / 特点等通用字段；
- 启动时 `mergeSeed()` 合并进本地知识库；菜单「知识库管理」可读取外部文件入库、导出备份、导入备份，还能「一键重新播种」。

这样即使不联网，智能助手也能基于本地骨干数据做问答与补全。

## 五、你也可以自定义提示词与模型

入口：设置 →「智能 AI 设置」。

- 添加自定义模型（OpenRouter / OpenAI 兼容 / 本地部署），填引用地址、模型 ID、API Key；
- 多模型管理与默认模型选择；
- 自动调用策略：仅默认 / 失败切换 / 轮询；
- 连接测试 + 配置导入导出。

改完保存即生效，下次智能查询就会走你配置的模型与策略。
